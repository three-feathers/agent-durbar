- **Notes: keep a folder's notes in the project, if you want** (spec 083 T042, issue 699): the folder's Notes screen has the switch *Also keep these notes as `.durbar/notes.md` in the project*, off by default. Turning it on asks first (*Cancel* focused): the file may be committed and pushed, text outside notes in an existing `notes.md` is removed, and an existing file's notes are counted and added as *From the project file*; inside a git repository a box (on) adds `.durbar/` to the clone's local `.git/info/exclude`. Turning it on and *Delete the file* also ask in a system dialog the page cannot answer; if the exclude line cannot be added the switch stays off until you choose to turn it on without it; the dialog counts lines of your own text an existing file would lose. Turning it off asks *Leave the file* or *Delete the file* (deleted only when it holds exactly what Durbar would write, never a link, and by a random name checked just before, which closes the swapped-folder race for a process that cannot read the other folder and narrows it otherwise; an empty `.durbar` goes too). It is not written into another folder put at the same path, and only turning the switch on creates the file. The file is masked with the token shapes and every known value of the folder and its open chats, waits while a secret is still locked, and is not written again by itself once it has disappeared. A file with merge conflicts or a failed write is shown on the screen and in the drawer. Not offered for a `.code-workspace`, greyed when the folder is missing; the simulator answers *Demo: no file written*. Checked with unit tests on temp folders (`test:notesswitch`) and a simulator driver (`check-notes-switch`); not run on Windows or macOS by a person.
