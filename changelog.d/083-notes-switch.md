- **Notes: keep a folder's notes in the project, if you want** (spec 083 T042, issue 699): the folder's Notes screen has the switch *Also keep these notes as `.durbar/notes.md` in the project*, off by default. Turning it on asks first (*Cancel* focused): the file may be committed and pushed, text outside notes in an existing `notes.md` is removed, and an existing file's notes are counted and added as *From the project file*; inside a git repository a box (on) adds `.durbar/` to the clone's local `.git/info/exclude`. Turning it off asks *Leave the file* or *Delete the file* (deleted only when it is exactly what Durbar last wrote, never a link; an empty `.durbar` goes too). A file with merge conflicts or a failed write is shown on the screen and in the drawer. Not offered for a `.code-workspace`, greyed when the folder is missing; the simulator answers *Demo: no file written*. Checked with unit tests on temp folders (`test:notesswitch`) and a simulator driver (`check-notes-switch`); not run on Windows or macOS by a person.
