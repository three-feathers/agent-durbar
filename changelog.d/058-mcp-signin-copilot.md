- **MCP Sign in for Copilot servers** (spec 058 FR-064..FR-069, FR-071, issue #364; tasks T098, T101, T102, T104): in a chat's **More > MCP servers**, a Copilot server that reads *Needs sign-in* has **Sign in**. Durbar asks Copilot's own runtime to start its sign-in (`mcp.oauth.login`, no token or callback ever passes through Durbar), shows "Sign-in page on *host*", and opens your browser only after you click **Open sign-in page** (https only, no user:password in the address, kept in memory for at most 10 minutes and dropped on Cancel, connected, End session or Restart session). The row updates when Copilot reports the server connected. **Switch off for this session** and *How to sign in from a terminal* (`copilot`, `/mcp auth <name>`, with **Copy**) are on the row; the steps show on their own where the runtime cannot start a sign-in. Claude Code and Codex rows are unchanged until their own PRs. Checked with the fake SDK, unit tests (`test:mcpsignin`, address-free replies and logs, the 10-minute limit, `http:` and user:password refused) and the simulator at 1440x900 and 1280x800 (`simmcpauth=1`, `simmcpauth=manual`); not run against a real Copilot account or server yet (T105).
