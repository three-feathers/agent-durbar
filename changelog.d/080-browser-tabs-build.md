- **Page tabs in the session browser** (spec 080 US6, FR-120..FR-133, issue 910): each session's browser holds up to 10 tabs in a strip above the address bar, with + (Ctrl+T, ⌘T), close (x, Ctrl+W, ⌘W, Delete in the strip) and Ctrl+Tab / Ctrl+Shift+Tab. The bar's ⋯ menu has *Open chat links in a new tab* (off by default, app-wide): with it on a chat link opens a new tab, and a link a tab already shows focuses that tab without reloading it; the link menu has *Open in a new tab*. A page's same-site `target=_blank` link opens a tab (http(s) only, 5 per page load); the tabs share the session's private profile, which is wiped once when the session ends; background tabs are dropped first when more than four pages are loaded. A page that opens a tab never takes the keyboard focus from the composer or the chat: the new page gets it only when the page that asked had it. Main decides every tab and checks every tab id. Checked on the simulator (`check-browser-tabs` at 1440x900 and 1280x800, `check:office` with 10 tabs) and in `test:browsertabs`, `test:browseripc`, `test:browserviews`, `test:browserpane`, `test:navigator`; not on Windows or macOS, and ⌘W in the bar on a Mac is unchecked.
