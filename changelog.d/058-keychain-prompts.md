- **Fewer macOS keychain prompts for Copilot and MCP sign-ins** (spec 058 FR-160, FR-161, issue #623): the mac package keeps GitHub's own signature on the bundled Copilot runtime instead of re-signing it ad-hoc, so the Keychain sees the same program as the `copilot` CLI and *Always Allow* holds across updates; a mac build fails if the signature is lost (`scripts/check-runtime-signature.js`). The one shared Copilot runtime now starts again after a failed start instead of failing for the rest of the run. Unit tests and the signatures of GitHub's mac packages; prompts not yet counted on a real Mac.
- **No extra connect attempts on a failed MCP server** (spec 058 FR-163, issue #623): opening a failed, pending or needs-sign-in server's tools no longer asks Copilot to connect it again (each attempt could show another macOS keychain prompt). Checked with fake-SDK tests.
