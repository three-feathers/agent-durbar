- **Fixed: a DPR 2 UI check on Linux no longer runs on a screen too small for its window** (spec 008 FR-213, issue #1591): `scripts/ui-suite.js` started each driver under `xvfb-run` with Xvfb's default 1280x1024 screen, so at `UI_SUITE_DPR=2` most of a 1440x900 window was off screen and painted-pixel checks could not see the lower rooms. The screen is now 1920x1100 times the density at colour depth 24 (`UI_SUITE_XVFB_SCREEN=WxHxD` overrides it). macOS and Windows are unchanged. Checked by `test:uisuite`; the Xvfb run itself was not done (no Linux here).
- **Fixed: `check-ui-text` no longer reads a dialog's buttons in their hover colours** (spec 008 FR-214): the real pointer rests where the window sits on the screen, so the larger Xvfb screen left it over End-all (4.14:1); the check now moves the pointer off the page first and fails with `is hovered at the read` if a control still is.
- **Fixed: two more colour-reading UI checks no longer depend on where the pointer rests** (spec 008 FR-214): `check-097-chat-contrast` and `shots-102-arcade` move the pointer off the page and assert no control is hovered before they read colours.
