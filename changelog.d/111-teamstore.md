- **Team templates have their store** (spec 111 T006, issue #1306): main keeps the templates in one file (`team-templates.json`, format `agent-durbar-team-templates`, at most 50), written by temp file, flush and rename (mode 0600 on POSIX; a folder the store creates gets 0700, an existing one keeps its mode), and a broken, newer, foreign-format or not-UTF-8 file is moved aside once as `team-templates.bad-<time>.json` with one notice (the newest 5 are kept). A read that fails once (at the load and before a save) is tried again before anything is moved or refused, and a file that still cannot be read at a save makes that save fail without touching it; a Windows rename held for a moment is retried. If another running instance saved meanwhile (the app takes no single-instance lock), a save (it re-reads the file and compares a SHA-256 of its bytes) is refused with `changed` and the store reloads, so a template saved by the other instance is not lost (except two saves in the very same instant: there is no lock). `isBlocked()` is true while a file it could not read at the load, or a bad file it could not move, is still in the way, and stays so until a save finds the file readable (nothing re-checks between saves). Such a save reads the file again first: a file that is readable and valid by then is reloaded and the save answers `changed`, never moved aside. A dangling symlink as the store file is moved aside like any bad file. Known gap: the folder is not flushed after the rename (same as schedules; see #1620). Leftover temp files of dead processes are removed. Nothing shows in the app yet. Tested with an in-memory file system (39 mutants killed) and with the real one in a temporary folder; not run on Windows or macOS (the 0600/0700 modes are POSIX only).
