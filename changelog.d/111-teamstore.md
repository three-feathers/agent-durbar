- **Team templates have their store** (spec 111 T006, issue #1306): main keeps the templates in one file (`team-templates.json`, format `agent-durbar-team-templates`, at most 50), written by temp file, flush and rename (mode 0600 on POSIX, folder 0700), and a broken, newer, foreign-format or not-UTF-8 file is moved aside once as `team-templates.bad-<time>.json` with one notice (the newest 5 are kept). A read that fails once (at the load and before a save) is tried again before anything is moved or refused; a Windows rename held for a moment is retried. If another running instance saved meanwhile (the app takes no single-instance lock), a save (it re-reads the file and compares a SHA-256 of its bytes) is refused with `changed` and the store reloads, so a template saved by the other instance is not lost (except two saves in the very same instant: there is no lock). Leftover temp files of dead processes are removed. Nothing shows in the app yet. Tested with an in-memory file system (33 mutants killed) and with the real one in a temporary folder; not run on Windows or macOS (the 0600/0700 modes are POSIX only).
