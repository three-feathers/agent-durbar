- **Search conversations does not list everything again for every query, and a session that does not answer cannot hold it up** (spec 095, issue 1904): the lists of earlier sessions (Copilot, Claude Code, Codex) and VS Code chats a search found are kept in memory for up to 5 minutes while the box stays filled, so a second query starts at once; opening Previous sessions for a folder, deleting a session, or a session leaving the office lists again. Each session read has its own 15 second limit: one that does not answer is skipped, counted in the end line ("N sessions that did not answer in time") and the search goes on. Checked in node tests with counting fake adapters and a runtime that never answers; not tried on a real store.
