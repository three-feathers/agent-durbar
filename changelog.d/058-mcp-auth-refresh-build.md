- **MCP sign-ins kept fresh** (spec 058 FR-204..FR-217, first part): before a chat's first message after an hour without a reply (or a wake from sleep), Agent Durbar asks Copilot or Claude Code to reconnect the chat's remote MCP servers, so the app renews an expired sign-in with its own refresh token. The message waits at most 5 s under one quiet line; Stop sends nothing; a server that still needs a sign-in gets a line with Sign in…. On by default (*Settings > MCP servers*); in Copilot's sandboxed modes (Read-only, Ask first) only the sign-in line, since a reconnect there did not renew the sign-in (Linux probe); Durbar never sees a token; no local server, no Codex chat, on macOS only servers that already need a sign-in. Simulator, fakes and unit tests; the apps' behaviour probed on Linux.
