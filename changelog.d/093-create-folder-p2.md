- **Clone a repository from + Folder** (spec 093 phase 2, issue #805): **+ Folder**, **File > New Folder…** and the palette's *Clone a repository* take an `https://` or ssh address (`git@host:owner/repo.git`, `ssh://…`); anything else (`file://`, `ext::`, `git://`, `http://`, local paths, a leading `-`, a password or a token in the address, also percent-encoded) is refused with the reason and the text kept. The name starts as the repository's; a progress dialog shows git's phase, percent and last lines (masked), the time so far, a "still waiting" line after 30 s without output, and **Cancel** (Escape too), which ends only the git Durbar started and then removes the half-made folder ("Cancelled. Nothing was kept."). Quitting during a clone does the same. In *Allow all* the confirmation names the host ("This code comes from github.com; agents can run it without asking."). The clone uses your own git credential helper and ssh agent and never prompts (ssh in BatchMode, also added to a plain-ssh `core.sshCommand`); only https and ssh can be used, through two independent layers that hold even against a git config that allows other transports or rewrites the address; submodules are not cloned; no hook runs during the clone; your environment's `GIT_*` variables are dropped except absolute `GIT_SSL_CAINFO`/`GIT_SSL_CAPATH`. Checked with the simulator at 1440x900 and 1280x800, fakes, and real git in tests against a local bare repository, a silent local listener and an ssh stub (Linux; CI also on Windows). **No clone over the network was run**, credential-helper sign-in windows are not checked yet, and it was not run on macOS before merge.
