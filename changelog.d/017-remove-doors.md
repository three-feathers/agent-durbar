- **No more doors** (spec 017, owner decision 2026-10-31, spec 021 FR-067): the **Office with cabins** layout and its Settings row, the door button on a desk, meeting-room signs, the waving and wallet poses, the flames, room door plates and **Close all** / **Open all** are gone. **Open office** is the only layout. **Hide folder** and floors stay, and so does the plain status word. Closed rooms open on the first start (`closed` in `durbar-folders.json` is dropped; `durbar.doorsigns` is no longer read). Scheduled prompts have no door check any more: a schedule for a session that had a closed door runs as normal. **Nothing held was sent:** a prompt that was queued behind a door when you updated stays queued; one notice asks once to **Send** (one by one, through the schedules), **Discard** or **Decide later**, and what is left stays in Settings > Schedules as **Held from before the update**. Remote control that a door had turned off stays off; the update never turns it on. Lost with the doors: one click to hold a session's schedules (use **Pause** or **Pause all schedules**, which skip a run instead of queuing it) and one click that also cut remote control (use **Stop remote control**). For MCP clients: `durbar_list_folders` no longer returns a `door` field (spec 041 FR-066). A saved theme that names `door-art` or `--door-*` still loads; they are ignored. Simulator-checked on Linux; not run on Windows or macOS or with a real session.
