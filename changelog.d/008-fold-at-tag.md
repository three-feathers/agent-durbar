- **Release notes come from the tag** (spec 008 FR-117..FR-120, owner-approved): a tag on `main` writes the draft's notes from exactly that commit's `changelog.d/` fragments, so the notes no longer go stale while the merge queue keeps landing PRs, and no merge freeze is needed. The release workflow refuses a tag that is not on `main`, does not match `package.json`, or comes before the previous release was folded. The draft is always a pre-release, never *latest*. The version lands first in its own PR, and the fold into `CHANGELOG.md` is a doc-only PR from the tag afterwards (`changelog.d/README.md`). Checked by unit tests on throwaway git repositories and a local dry run; the workflow itself has not run on GitHub yet.
