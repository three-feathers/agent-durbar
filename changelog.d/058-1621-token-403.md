- **A refused MCP token no longer asks you to sign in** (spec 058 FR-232, issue #1621): when a remote MCP server whose entry sends its own token (a header, or a `${NAME}` variable) and has no OAuth answers 403, its row now reads *Refused: token not accepted* with "check the header or the variable it uses" instead of *Refused: needs sign-in*, and no longer offers *Sign in again…*, which could not change a header. When the header uses a variable that Agent Durbar's own environment does not have (an app opened from the Dock or a desktop menu does not read your terminal's profile), the row names that variable, never its value. A 401 and servers with OAuth keep the sign-in. Unit tests and the simulator; not checked against a real server.
