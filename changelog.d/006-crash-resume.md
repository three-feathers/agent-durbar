- **Resume interrupted sessions after a crash** (spec 006 FR-038..FR-046, issue #606): if Durbar stopped unexpectedly (crash, kill, power loss) while sessions were working, the next start shows one card, "N sessions were interrupted", with **Resume all**, **Pick…** and **Dismiss**. Resume uses the existing resume (each session's own mode and cap, its earlier chat shown, no prompt sent); the chat says the unfinished reply is lost and nothing was sent again. Nothing resumes by itself. A small marker file of session ids per Durbar process (mode 0600, no content) is removed on a normal exit, and a second Durbar running on the same profile is not taken for a crash. In a lounge corner made short by the strips, a resting agent's chat number no longer covers its name. Unit tests (`test:crashmarker`, with mutations) and a driver at 1440x900 and 1280x800 on the simulator (`DURBAR_SIM_CRASH=3`); no real crash run, not checked on macOS or Windows.
