- **Folder status never runs a command from the folder's own git config** (spec 063 FR-008, #719; found by Ruben's agent in the review of #718). Git honours a folder's `.git/config`, so a planted `core.fsmonitor`, filter driver (`clean`/`process`), external diff or textconv, or the `core.sshCommand` of a partial clone's lazy fetch could run while Durbar read the branch and changed files. Every git call now goes through one runner that allows only `status`, `diff`, `rev-parse` and `rev-list`, turns those settings off on the command line (`-c`, `--no-ext-diff --no-textconv`, no transports, no lazy fetch), switches off each configured filter driver, and does not enter submodules for their uncommitted changes (a moved submodule commit still shows). Tested with real git 2.43 on Linux; not run by hand on Windows or macOS.
