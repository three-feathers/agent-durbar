- **A schedule's run history, and "Schedules here (N)"** (spec 044 FR-036..FR-045, issue #624, owner request): every Durbar schedule's row, in the folder's dialog and in Settings > Schedules, has a **History** button that lists its last 50 runs under it, newest first, each in words with an icon (sent, sent with Run now, skipped because the agent was busy or paused, not sent at its limit or after its session ended, missed, could not send with the reason, held at a closed door, loop ended). A busy, paused or held skip that repeats is one line with a count ("4 times, until 08:45"). **Open chat** goes to the chat a run went to; a chat that is gone says *chat closed*. The schedules file is now saved safer (a private temp file, fsynced and renamed over it, a failed write kept and retried, a file that cannot be read is moved to `.bad-<time>` instead of being overwritten). The log is kept by the app next to the schedules (no prompt text, error text, path or token in it; old files load as they were; deleted with the schedule), and the window asks for one schedule's log only while its list is open. The folder's menu item and the Folders panel button now read **Schedules here (N)** and open the same folder dialog as before. Checked with unit tests (`test:schedules`, `test:schedhist`, `test:ipcchannels`) and the simulator driver `check:sched-history` at 1440x900 and 1280x800; not seen on a Mac or Windows, and a real session's id surviving a restart (for Open chat on older runs) is not verified.
