- **Deleting the project notes file never renames anything back over a `notes.md`** (spec 083 FR-055, issue #1463): when *Delete the file* could not finish and the safe way back (a hard link) failed, Durbar renamed its file back to `notes.md`, and a folder link swapped in that instant could make the rename replace a `notes.md` in another folder. Now the file stays in `.durbar/notes` under the random name the message gives (on drives without hard links too). The remaining race, a link swapped within microseconds by a local process, is recorded in the spec and `docs/safety.md`; closing it is issue #1464. Checked by unit tests with injected file calls and a real swapper process, Linux only.
