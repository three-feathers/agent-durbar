- **Deleting the project notes file deletes only the file Durbar wrote, and never renames anything back over a `notes.md`** (spec 083 FR-055, issue #1463): a folder link swapped within microseconds by a local process (for example a sandboxed agent) could make *Delete the file* delete a `notes.md` with Durbar's text in another folder, or make the way back replace another folder's `notes.md`. Durbar now records the inode of the file it writes and deletes only that one (a `notes.md` with the same text in another inode, after a `git checkout`, is left as changed); the way back is a hard link, or on drives without hard links a copy into a new `notes.md` that never replaces a file, and the random name is dropped only when the new `notes.md` is confirmed. Still open, recorded in the spec and `docs/safety.md`: such a swap can move another folder's `notes.md` into the project under a random name (named in the message), a delete with no inode record (written before this version, or on a drive without inode numbers) can still delete it, and a write can still overwrite it; closing that is issue #1464. Checked by unit tests with injected file calls and a real swapper process, Linux only.
