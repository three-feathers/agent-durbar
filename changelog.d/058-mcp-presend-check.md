- **Copilot MCP sign-ins are checked in the background before every message** (spec 058, issue #1205): beside each message you send, and when a chat starts, Agent Durbar asks every remote sign-in server that reads *connected* for its tool list (a real round-trip, no AI, no credits; your message is never held; a server with a successful call or check in the last 5 minutes is skipped). A server that answers *unauthorized* is reconnected at once; only a clear sign-in signal counts (an HTTP 401, Copilot's own "OAuth challenge required", `invalid_grant`, an Entra sign-in code), so other errors restart nothing and a server that answers its tool list is not restarted by the check (a reconnect before a message after a quiet hour is a separate rule); a server is checked at most once every 5 minutes; one that does not answer in 30 seconds is marked *Did not answer a check* on its row (that request is not cancelled in the runtime, and no second one is sent while it is outstanding). Nothing shows in the chat while all is well, only *Reconnecting <name>…* during a reconnect, and the agent gets no extra message from it. New *Settings > Diagnostics* (off by default): the activity-log row *renewed (automatic)* is now written only with it on. Probed on a local test server only; not checked on a real Entra server, macOS or Windows.
