- **Parity checklists tick themselves** (spec 021 FR-088): when an issue on the Real office (#1147) or Retro arcade (#1404) parity checklist is closed as completed, a workflow ticks its line; reopening unticks it. Each run reconciles every line with the live issue states, so no close is lost when runs queue up; a daily run is the backstop. It uses `issues: write`, a read-only checkout of `main`, and no value of the event. Checked by `test:paritytick` (transform, trust gates, cancelled runs and workflow shape, with mutants); the workflow itself first runs after merge.
