# Development and how we work

Build, test and run from source; the npm scripts; the spec-driven way of working. Moved out of the [README](../README.md) on 2026-10-31 so the README stays short (spec 021 FR-065); the text is unchanged except for its links.

## Build from source

```bash
npm ci
npm run typecheck && npm run build && npm test   # unit suites in parallel (~20 s); `npm test -- folders` filters; `npm test -- --bail` (or `TEST_BAIL=1`) stops at the first failing suite, for iterating, and the final run still runs everything
npm start                 # the app, with the harnesses you have installed and signed in
DURBAR_SIM=15 npm start   # 15 simulated agents: no sessions, no AI credits (main refuses every call that could reach a real agent app)
npm run test:claudecli    # opt-in, not in `npm test`: the flags Durbar's Claude adapter can send against every installed Claude Code CLI's `--help` (~/.local/share/claude/versions/*, `claude` on PATH, or DURBAR_CLAUDE_BINS=path:path); only `--version` and `--help`, no session, no credits
DURBAR_CLAUDE_BIN=/abs/path/claude npm start   # dev/test only: use that Claude Code file first (absolute path to an existing file; ignored in a packaged build; prints a warning)
npm run check:perf -- --record perf.json   # spec 097 T145: records frame, CPU, memory and switch rows for flat and Real office at 15 and 40 agents (simulator, no credits, no asserts; pure Node, runs on macOS and Windows; `--gpu` adds the real-GPU A/B rows, `--quick` is a smoke, `--only real-15`); the record names the OS, pixel ratio and `gpu_compositing`
npm run check:world-distinct   # spec 102 FR-016, T093: decodes every world's pictures in a hidden Electron window (not the app, no network) and fails a copied, recoloured or re-encoded fixture or the same average colour of wall, floor or desk; `-- --measure` prints the distances; the World matrix workflow runs it in its subset and weekly jobs; by hand, run it under the Electron lock (`scripts/run-electron-script.js` puts `--no-sandbox` on the command line on Linux only, and the script stops with a message naming the step after 30 s a decode or 60 s in all). The exact-copy half is `test:world-distinct`, in `npm test`
npm run world:contact-sheet   # spec 102 FR-017, T094: one JPEG of every world's pictures side by side, in `out/world-contact-sheet/` (git-ignored, never committed), for the owner's look; the look is recorded by a person in the card's `distinct-check` (`pending` until then); Electron, under the lock
npm run world:matrix      # spec 098: world moment x world pictures and checks into out/world-matrix/ (git-ignored; Electron, simulator only; -- --size 1280x800 --worlds photo --forced-colors; `node scripts/world-matrix.js --selftest` proves its checks). CI: world-matrix.yml, weekly and a path-filtered PR subset, artifacts for 14 days
npm run check:office      # layout check at 1440x900 and 1280x800 (Electron; xvfb on Linux), simulator only
npm run shots:docs        # retake every screenshot the README and the website link (simulator, one Electron at a time; -- --only, --list, --out <dir>); every picture it writes is palette-compressed (about 60% smaller, with a quality guard); it also retakes the world previews (spec 102 FR-302) into `src/renderer/realoffice/previews/`, WebP under 48 KB, as the driver wrote them (`scripts/shots-102-previews.js`, `?simscene=preview`)
npm run icons:build      # by hand, one offscreen Electron: rebuilds build/icon.{svg,png,ico,icns}, build/logo/icons.json and src/renderer/logo-marks.js from the drawings in build/logo (spec 101); test:logo-assets fails when they are stale
npm run shots:compress    # compress screenshots by hand: the linked ones, or the files you name (-- --check only lists; DURBAR_SHOTS_COMPRESS=off turns it off in shots:docs)
npm run release:video -- --version vX.Y.Z --out <dir>   # a 30-60 s clip of a release's changes from the simulator (MP4 + GIF, eased zooms on what changed, needs ffmpeg; spec 008 FR-171..FR-178; trial, not in the release flow yet)
npm run usage:receiver    # spec 008 FR-181: a local receiver (127.0.0.1:4318, needs DURBAR_USAGE_MACHINE) that sums Claude Code's OpenTelemetry token and cost metrics per day and model into ~/.durbar-usage; docs/build-cost.md
npm run usage:day -- --date YYYY-MM-DD [--files a.json,b.json]   # the Build cost markdown table per machine and model (API list-price estimate, not billing)
npm run usage:readme -- --release vX.Y.Z   # in the fold PR after a release: rewrites the README's Build cost block, adds the release's row to docs/build-cost-history.json, regenerates docs/build-cost-badge.svg and docs/build-cost.svg (pure text, no network; `--check` writes nothing)
npm run check:geometry    # the dark fixture theme lays out exactly like Clean Office (CHECK_ALL_THEMES=1: every fixture theme, about a minute)
npm run check:ui          # every simulator driver that asserts, one after another, on any OS (UI_SUITE_XVFB=1 keeps windows off a Linux desktop); -- --list names them, -- --only check-notes,check-edits runs just those
npm run check:themes      # on demand: the full layout check in every theme, a few at a time, low priority, memory limits
npm run pack:dir          # (CI: a step of the required check "Office layout check (xvfb)", which covers packaging on Linux, spec 008 FR-194) unpacked app for this OS in release/ (also dist, dist:mac:arm64, dist:mac:x64, dist:win, dist:linux; unsigned); then checks the Electron fuses and the display names
node scripts/electron-cache.js plan|seed|warm   # CI only (spec 008 FR-195): the Electron download cache of .github/actions/npm-ci; electron-cache.yml warms main's entry for every runner OS (push to main, nightly, by hand), so a GitHub release-download outage does not fail PR jobs; npm ci retries 4 times, 7.5 minutes of waits by default (input retry-waits for a short job); test:electroncache checks every job's timeout against it
npm run check:fuses-launch  # on demand, after pack:dir: the packed Linux app opens its window and offers no debugger (xvfb on Linux)
npm run specs:index       # the full specs index from each spec's specs-index block, into specs/INDEX.md (git-ignored); --add specs/NNN-x for a new spec; specs:check in npm test, which also refuses conflict markers
npm run labels:backfill   # dry run: the labels each issue and PR is missing (spec 021 FR-045); -- --create-labels --apply adds them (add-only)
npm run changelog:check   # check the changelog.d/ fragments (in npm test); changelog:preview lists them; a tag's notes come from them, then changelog:build folds them (changelog.d/README.md)
npm run blog:check        # spec 104: the agent blog's guard over docs/site/{blog,captions,story,explainers}: tokens (redact.ts), private paths, addresses, chat markers, unreleased phrases, a host allowlist and blocked-name hashes, first names, evidence, security hold, who reads and reviews (in npm test through test:site; -- --offline skips the online author check and says so). The file, line and rule are printed, never the matched text. `node scripts/check-posts.js --add-blocked-host` is a human step that reads one name from stdin and prints nothing
npm run rules:check       # word budgets of the rule files (AGENTS.md, docs/rules/, CLAUDE.md, agent notes, checklist, ...; in npm test; every docs/rules file linked from AGENTS.md): one rule in, one rule out
npm run specs:numbers     # NETWORK, not in npm test: fails when an FR-, T- or Q- number your branch adds is also added by another open PR head or already on origin/main, per spec file (spec 021 FR-085); run it before every push; also a job of spec-kit.yml
node scripts/picture-budget.js   # offline, in npm test (test:picturebudget; CI's npm test has no origin/main, the spec-numbers job runs it --strict): fails a picture or media file (by name or first bytes), added or changed since the merge-base with origin/main, even one a later commit replaced, over 300 KB; fix with compress-shots or keep it local; allow-list scripts/picture-budget-allow.txt (reason per line)
```

`npm run smoke` and `npm run verify:cap` use a real Copilot login and may spend credits: run them only on purpose. Under `DURBAR_SIM` the main process refuses every window call except the install-route list and the app version and never creates a real adapter, so a simulator run or driver cannot spend credits; a deliberate real check runs without `DURBAR_SIM` (spec 010 FR-022..FR-027). The **E2E real accounts** workflow (spec 062) installs the three agent apps on Linux, macOS and Windows, signs in with the CI account's secrets and lists models every day; one tiny turn each (Claude on Haiku, Codex on a small model) runs daily on Linux and, on macOS and Windows, on Mondays or by hand with `full_turn`. It was paused 2026-10-29 to 2026-11-02 (red since 2026-10-25, issue #856; the cause was an agent app's OS sandbox that cannot start on a runner, now taken like a person would) and runs once a day and by hand again, never on a push or a pull request. The supported CI platforms are listed once, in `.github/platforms.json`. GitHub Actions also runs the UI checks (geometry, office layout, the Mac title bar, `check:ui`) on Windows and Linux for each pull request that changes something the app, its build or the UI drivers use (spec 008 FR-191: a tooling, report or unit-test script, docs or a version-only bump skip it; pushes to `main`, the nightly and by-hand runs always run it; the merge queue runs `ci.yml` in full but not this workflow, as before), and on macOS nightly, and keeps the screenshots of each run (workflow *UI on three OSes*; simulator only). macOS does not run on pull requests: build and test runs on every push to `main`, the other macOS checks nightly, and a failed nightly run opens an issue (spec 008 FR-106). Releases are built by GitHub Actions from `v*` tags on `main` into a draft release that the maintainer publishes by hand; a test-build tag (`v0.1.0-alpha.N-test.M`) builds a draft pre-release from any branch, with the unmerged commits as its notes (spec 008 FR-121).

**Layout of the repository:**
- `src/main` (Electron main), `src/preload`, `src/renderer` (plain HTML/CSS/JS, the simulator);
- `src/adapters` (Copilot, Claude Code and Codex adapters, the permission broker), `src/shared`;
- `scripts/` (tests and screenshot drivers), `specs/` (Spec Kit specs), `docs/`.

## How we work

Agent Durbar is spec-driven with [GitHub Spec Kit](https://github.com/github/spec-kit): **no code without a spec, a plan and tasks.**
- Every feature has a folder in [`specs/`](../specs/README.md). Each requirement is tagged `[IMPLEMENTED]` or `[KNOWN GAP]`, with how it was checked.
- The rules are in the [constitution](../.specify/memory/constitution.md).
- A CI check fails a pull request that changes `src/` without changing `specs/`.
- Coding agents follow [AGENTS.md](../AGENTS.md). People start with [CONTRIBUTING.md](../CONTRIBUTING.md) and [docs/collaboration.md](collaboration.md).
- Claim an issue on the [project board](https://github.com/orgs/three-feathers/projects/1) before you start.
