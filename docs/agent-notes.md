# Agent notes

What coding agents on this repo learned the hard way, so the next agent does not have to. The rule to keep this file up to date is in [AGENTS.md](../AGENTS.md) (*Share what you learn*); team rules live there, not here.

Each entry has the date it was learned, what happened, and how to apply it, with its evidence (`real:` = run and seen, `read:` = from code or docs, a PR or issue number). Add an entry in the PR where you learned it. Fix or delete an entry that turns out to be wrong. **Never** put secrets, tokens, personal data or chat contents here.

## Shell and process pitfalls

- **`pkill -f` / `pgrep -f` match their own shell** (2026-10-20). The pattern is in the command line of the shell that runs it, so a kill can end your own command (exit 144) and leave half-done state. The `[c]har` trick is not enough when the same command line also contains the plain name (a heredoc, a comment, a later `nohup <script>`). Do the kill in its own command, select targets by a field (`ps -eo pid,args | awk '$3 ~ /name/'`), or better, keep the PIDs of what you start.
- **Hand-run `claude` loads your plugins** (2026-10-19, `real:`). A plain `claude -p ...` probe loads the user's plugins and MCP servers; a chat-channel plugin then takes over the running session's bot and dies with the probe. Always pass `--strict-mcp-config --setting-sources ""` on a hand-run `claude`. Durbar's own adapter already passes its own `--setting-sources`.
- **Electron checks are heavy.** Run at most two Electron drivers at once, under `nice -n 10`, and keep the limits in `scripts/run-tests.js` and `scripts/check-parallel.js` so the computer stays usable. Run long checks in the background.

## CI, review and merge

- **Wait until every check has settled** (2026-10-20). Some workflows only add their checks after the first set finishes, so "no pending check" right after a push can be a false green. Before merging, wait until no check is pending through a quiet period (about 90 s), and require the CodeQL check itself to have passed.
- **A review can be a plain comment** (2026-10-20, PR #389). Paco's agent posted its required change as a normal PR comment, not as a *request changes* review, and a merge helper that looked only at checks and bot comments would have merged past it. Read every comment kind (`issues/<N>/comments`, `pulls/<N>/reviews`, `pulls/<N>/comments`, and unresolved `reviewThreads`); `scripts/pr-gate.sh <N>` lists those newer than your own last reply.
- **Bot comments can outlive their alert** (2026-10-20, PR #388). GitHub moves a line comment to the newest commit while its line still exists, even after the CodeQL alert was fixed. Gate on open alerts (`code-scanning/alerts?ref=refs/pull/<N>/merge` and `/head`), not on the bot-comment count; read the comment, then check the alert's state.
- **Read the PR's own security results**, not only `main`'s alerts: `gh pr checks <N>`, the bot's line comments (`gh api repos/{owner}/{repo}/pulls/<N>/comments`), and `code-scanning/alerts?ref=refs/pull/<N>/merge&state=open`. A comment on an old commit may be stale: compare its `commit_id` with the head.
- **Values spliced into page code in drivers** (2026-10-20, CodeQL `js/bad-code-sanitization`, PRs #348, #358). `JSON.stringify(x)` inside a `ctx.js(\`...\`)` string is flagged. Use `jsLiteral` from `scripts/check-office-overlap.js` for every value put into page code.
- **Static source checks and CRLF** (2026-10-20, PR #379, Windows CI). On Windows the checkout has CRLF endings, so `src.split('\n')` leaves a `\r` and a regex anchored with `$` never matches. Split with `/\r?\n/` or `trimEnd()` each line. The same bit the site test earlier.
- **Re-approval after a push: compare patch ids** (2026-10-20). See AGENTS.md *Re-approving after a push*; `git patch-id --stable` on the PR's own `src`/`scripts` diff tells you whether the code changed.
- **Union-merging CHANGELOG and index conflicts can duplicate rows** (2026-10-20). Keeping both sides of a conflict in `CHANGELOG.md`, `specs/README.md`, `README.md` or a `tasks.md` often leaves the old and the new version of the same row. After resolving, count rows per spec (`grep -c "^| \[012\]" specs/README.md`) and per task id, and merge duplicates by hand.
- **Reviewing a masking or parsing change** (2026-10-20, PR #369). Fuzz it: plant one secret in 20 or so shapes (flags, `export`, `$env:`, JSON, cookies, connection strings, escaped JSON) inside 10 or so wrappers (`sh -c`, `cmd /c`, PowerShell `-Command`, nested shells, quoted args), and compare leaks against `main`. Time hostile inputs too, and include **one long word** (`';'.repeat(n) + 'x y'`, runs of backticks): repeating short space-separated units misses quadratic regexes. Check that the time grows linearly from 20k to 200k characters.
- **Fuzzing shell wrappers: build the args form the OS really passes** (2026-10-21, #447, T067). For `sh -c` the OS removes one quoting level, so the script arg is the decoded text; `cmd /c` and `powershell -Command` parse their own command line, so their args keep `^`, `` ` `` and `''` escapes and cmd/PowerShell join every arg after the flag. A fuzz that keeps the outer quotes in the arg reports leaks that cannot happen, and one that strips the cmd/PowerShell escapes misses real ones. Also: `redact()` and the scheme rule take a `\` in their value class, so running them on raw escaped text (`Bearer x\"`) eats the backslash and breaks the quoting; only escape-aware rules (`maskEscapedPairs`) may run before a decode. And cut a repeated unit at the same phase for both sizes in a linearity row: a cut inside an unclosed quote takes a fail-closed fast path and makes the ratio look quadratic. Evidence: `test:` `scripts/test-redact.ts` §14d.
- **Claude Code's auto mode refuses agent merges** (2026-10-20, `real:`, PRs #339, #369, #377). Its safety classifier denies `gh pr merge --admin --merge` as "Merge Without Review" even with a fresh approval, green CI and a `Bash(gh pr merge *)` allow rule. It sometimes also denies a chat message that asks the human to merge. Do not retry or reword the command: tell your human the exact command, or ask them to press Merge.
- **Every push dismisses approvals, and `main` moves fast** (2026-10-20, PRs #369, #377). Each merge of `main` cost a fresh approval, and the branch was conflicting again within the hour (CHANGELOG). Ask for re-approval only once CI is green on the new head. Batch docs-only edits into one push, and point the reviewer to the patch-id check.
- **Mutation checks** catch tests that pass for the wrong reason: undo the fix (or change the wiring) by hand and see the test fail before you trust it.
- **A test that awaits a promise that never settles passes** (2026-10-21, PR #473, found by Paco's agent). Node exits with code 0 when nothing is left on the event loop, without running the rest of `main()` or printing PASS, and `run-tests.js` reports ok. A "second call is refused while the first runs" test that `await`s the second call before releasing the first hangs exactly that way once the lock is gone. Start both calls, assert on what is synchronous (calls that reached the fake), release, then `await Promise.all`; and guard the script with `process.on('exit')` that sets `process.exitCode = 1` when a `done` flag was never set (`scripts/test-mcp-session.ts`).
- **End-anchored regexes on untrusted text can be quadratic** (2026-10-21, PR #463 review, `test:` timing cases). `/\s+$/`, `/\n+$/`, `/[ \t]+$/` and a lazy `(.+?)\s*$` retry the whole run at every position when a long run of blanks or newlines is followed by other text: 100,000 spaces in a streamed `Write` took 61 s in the main process. On model output, agent args or diffs use `trimEnd()`, a greedy capture plus `trimEnd()`, or a loop from the end, and add a timing case built so the run is *not* at the end (a run at the very end matches at once and hides the bug). Test the old code in its own process with a timeout: the cases can take minutes.
- **`until` in `scripts/driver-helpers.js` never throws** (2026-10-21, PR #463). A driver that only `await until(...)`s passes even when the condition never came true; assert on its result (`assert.ok(await until(...), msg)`), and mutation-check the new step.

## Simulator and drivers

- **One window global per renderer script** (2026-10-21, issue #474, `sim:`). The renderer's helper files are plain scripts that publish their API as `root.DurbarX=api`; a second file with the same name silently replaces the first (here `activitytable.js` and `activity.js` were both `DurbarActivity`, so Tools > Activity threw). Node tests `require` each file directly and never see the clash. *How to apply:* give a new renderer file its own `Durbar*` name; `npm run test:globals` fails on a duplicate. A screen that no driver opens can break unseen: add a driver that opens it.
- **Timing the renderer from a driver** (2026-10-21, `sim:`, spec 001 FR-033). `app.js` is one IIFE, so a driver cannot wrap `chooseLayout` or `renderOffice` from outside. To time or inspect them, patch a **copy** of the built `dist/renderer/app.js` (rename `function chooseLayout(` to a wrapper that records `performance.now()`, and expose what you need on `window` before the final `})();`), never `src/`. Machines here are shared and loaded: run old and new builds **alternately**, several rounds, and compare medians; a single run can be 30% off.
- **What a layout costs is style, not layout** (2026-10-21, `sim:`, spec 001 FR-033). In the hidden `#probe` a trial was about 7 ms of style recalculation, 5 ms of parsing and only 1.5 ms of layout. Two cheap wins that keep every box: leave out what is inside an `<svg>` (its box never depends on its children), and register custom properties that only their own element reads as `@property --x{syntax:"*";inherits:false}`, so changing them does not restyle every descendant. `contain`, moving the probe out of flow and dropping the `:has()` rules made no difference.
- **A desk scene is only redrawn when its `data-sig` changes** (2026-10-21, `sim:`, spec 040 FR-023). The office patches the DOM by key and `morphNode` keeps a scene SVG whose signature is unchanged, so anything a scene draws must be in its signature, the active theme included (`THEME.themeIdForCache()`), or a switch leaves the old drawing. A driver that clears `#stage` before its screenshot (as `shots-themes.js` does) hides such a bug: switch through the real path (Settings) and assert on the DOM. Figures built once (walkers) need the same key.
- **Theme values: two copies, one corpus** (2026-10-21, spec 070). The renderer's `theme.js` cannot import a TS module in the page and main needs the same rules, so the typed-token grammar lives in `theme.js` and `src/shared/themetokens.ts`. Change both, then run `test:theme-tokens`: it feeds one corpus to both and fails on any difference. A new colour literal in the renderer's CSS or JS fails the same test (a ratchet per file); use a token, or lower the ratchet when you remove literals (`THEME_LITERALS_WRITE=1 npm run test:theme-tokens`). A non-colour token is set on `<html>` only when the pack gives it: an inline custom property beats `html[data-ui=...]` rules in `themes.css`.
- **`app.js` is one IIFE** (2026-10-21, spec 003 T030): `bridge`, `sim` and the helpers are not globals, so a driver's `ctx.js('bridge.x()')` reaches something else (or throws). Assert on the DOM, or move the logic into a pure function in `src/main` and unit-test it (as `resumeModeOp`).
- **`until` in `driver-helpers.js` does not throw** (2026-10-21, `sim:`, spec 058). On a timeout it prints `[waits] timed out ...` and returns `false`; the driver goes on and can print PASS. Assert what you waited for (`assert.ok(await until(...))`, or a check right after), never rely on `until` alone. Also: a renderer handler that repaints with `await load()` right after starting a bridge call through `Promise.resolve().then(...)` reads the state before the call has run (microtask order); start the call first, synchronously, then repaint.
- **`shots-033` needs floors**: run it with `DURBAR_SIM_FLOORS=1` (and `SHOTS_033=<dir>`), or it fails with a page-script error.
- **Previous sessions sit behind "Previous (N)"** in the chat header since spec 052 round 10; `#prev` stays hidden until opened. A driver that checks the history reads `#prevBtn`'s title or clicks it first.
- **Chat settings live under the message box** (2026-10-21, `sim:`, spec 005 FR-037..FR-043). `#modeChip`, `#modelChip`, `#agentChip`, `#ctxChip` and `#mcpBtn` (no longer in More) are in `#cToolbar` under `#msgInput`; `#stopBtn` sits in `#runSlot` inside the box and is `hidden` unless a turn runs; **Compact** (`#compactBtn`) exists only while the context chip's menu `#ctxMenu` is open. A driver that clicks Compact opens `#ctxChip` first. With a narrow panel, controls can sit in the `#ctMorePop` popover (same ids): check `getClientRects()` before asserting visibility.
- **A screenshot with `blur: true` moves Escape** (2026-10-21, `sim:`). `H.shot(..., { prep: 'calm', blur: true })` blurs the focused element, so a following `key('Escape')` goes to the page and closes the chat (Esc = Back to the office), not the open menu. Take that shot without `blur`, or after the Escape. The same in the page: re-appending a focused DOM node (moving it to another parent) drops its focus; put it back with `focus({preventScroll:true})`.
- **Top bar ids since round 11** (spec 052 FR-105): the defaults selects (`#kindSel`, `#permMode`, `#modelSel`, ...) are inside the `#defaultsPop` popover, opened by `#defaultsBtn`; *Add folder* and *Add VS Code workspace* are plain top-bar buttons again since FR-164 (2026-10-21: `#addFolder`, `#addWs`, no `#newMenu`). Open the popover before checking visibility. The brand name can be visually hidden (`.topbar.tb-tight`, set by `fitTopbar` when the row would wrap): after forcing a font or the Mac platform in a check, call `window.DurbarFit()` so the bar is refitted.

- **A failing driver now exits 1** (2026-10-20, spec 008 FR-090). Before that, Electron printed "DRIVER FAILED" and exited 0, so only a log grep caught a failure. `scripts/ui-suite.js` (`npm run check:ui`) runs every asserting driver with the settings it needs (`shots-033` needs floors, `shots-001-welcome` runs without the simulator, `shots-model` per size); add a new asserting driver to its list. On Linux with a desktop, set `UI_SUITE_XVFB=1` or the windows open on your screen.
- **Check the PR's bot comments on the head commit, not only the merge-ref alerts** (2026-10-20, PR #388). An alert list of 0 can hide a fresh CodeQL line comment. The other way round, GitHub carries a line comment forward to a newer commit while its line still exists, even after the alert is fixed: then read the alert's instances (`code-scanning/alerts/<n>/instances`) and check its state on `refs/pull/<N>/head`.

- **Measure top-bar fit in CI's font, in Electron** (2026-10-21, `real:` FR-164). The top bar is about 30-60px wider in DejaVu Sans (Ubuntu CI) than in Noto Sans, and a theme's display font (European court) widens the brand by 40px. Run any driver with `FONTCONFIG_FILE` pointing at a fontconfig that lists only `/usr/share/fonts/truetype/dejavu` and `.../liberation` (recipe in `check-office-overlap.js`): Electron then uses DejaVu everywhere. Measure with floors and `simkinds=mixed` (the widest bar), in every theme, Expert and Simple, and with `data-platform="darwin"` forced (+58px) before calling a width rule done.

- **Time budgets on a loaded machine: subtract the run-queue wait, not the budget** (2026-10-21, issue #454, `real:`). A check that times the app with the wall clock fails when other processes take the CPU (shots-033 SC-003: 530-890 ms against 500 under 6 CPU burners, 200-310 ms quiet). A short CPU-bound calibration loop in the driver did **not** see that load (it read 1.1x while the renderer lost half its time: Linux favours a thread that just woke up), so do not scale by one. What worked: let the app time its own work (a `performance.mark`/`measure` pair around it, read by the driver), and on Linux subtract the renderer main thread's run-queue wait over the same span, field 2 of `/proc/<webContents.getOSProcessId()>/schedstat` in ns. Under load the counted figure matched the quiet one (217-343 vs 199-311 ms), and injected work or a timer wait still failed. Where the file is missing (macOS, Windows), keep the wall time.

- **`data-lbl-simple` / `data-lbl-expert` only on leaf elements** (2026-10-21, spec 005). `relabelScopes()` in `app.js` sets `textContent` of every element that has them when the detail level switches, so on a container (a `<details>`) it wipes the children. Put them on the `<summary>` or the button itself.
- **`.place.busy` no longer means a tool walk happened** (2026-10-21, spec 068, `real:` macOS CI theme geometry). The coffee corner is busy at once when an agent goes on a break (Omar hits his cap at load), so a check that waits for "some place is busy" may measure before the 600 ms tool walks. Wait for `.place.busy:not([data-place="coffee"])` (as `check-theme-geometry`, `check-office-overlap`, `shots-themes` and `shots-024` now do).
- **A dark-theme screenshot needs a user manifest** (2026-10-21, `sim:` spec 043 T012d). No built-in theme has a dark surface (Retro Pixel only has a dark floor), so a "light and dark" check passes a spec 040 manifest to `window.THEME.setTheme({id, extends:'clean-office', tokens:{...}})` in the page (`shots-043-editor.js` has one). The chat's `.md` code and table colours are light-only hex values; scope a token override to your own container instead of changing `.md` for every chat.
- **jsdom has no `localStorage` on a `file:` URL** (2026-10-21, `test:` spec 043). A renderer script that reads `window.localStorage` throws there; give the JSDOM an `http://localhost/` URL in unit tests.

## Electron and platform behaviour

- **`safeStorage` is keyed by the app name** (2026-10-20, `real:` Linux gnome-libsecret; `read:` Electron source for macOS Keychain). Calling `app.setName()` **before** `ready` makes a new key, so secrets saved under the old name no longer decrypt; calling it inside `whenReady` kept the old key in the test. Durbar does not call `setName` at all (PR #377): the identity stays `agent-durbar` and only the menu labels say "Agent Durbar". Do not add a `setName` call; `test-profiledir` fails if you do.
- **macOS Keychain and unsigned builds** (2026-10-21, `read:` Chromium `os_crypt_mac`, Apple Keychain docs; not seen on a Mac). Every `safeStorage` call, `isEncryptionAvailable()` included, can read the Keychain item `agent-durbar Safe Storage`, and an app the item does not trust gets a prompt. Ad-hoc signed builds (`identity: "-"`) are a new app to the Keychain after every update, so "Always Allow" does not survive an update. How to apply: never decrypt in a loop or at load; keep secrets in one blob read lazily once per run (`McpStore`, spec 019 FR-023), and test it with a counting fake codec. The Copilot runtime inside the bundle reads Copilot's own Keychain items too; those prompts are not Durbar's store. Since spec 058 FR-070 (2026-10-21, `read:` SDK `types.d.ts` `mcpOAuthTokenStorage`) Copilot sessions set `persistent`, so the runtime also writes and reads MCP OAuth sign-ins in the OS keychain: expect up to one more prompt per signed-in server on a Mac (not counted on a real Mac). Do not "fix" those prompts by switching back to `in-memory`: that loses the sign-in at every session end (owner's Q12 B).
- **Profile folders** (PR #377): installed builds use `<appData>/agent-durbar`, `npm start` and the simulator use `<appData>/agent-durbar-dev`, and `DURBAR_USER_DATA` (dev hooks on) wins. Use `DURBAR_USER_DATA=<folder>` to run against an existing profile.

- **A `src/shared` module in the page** (2026-10-21, `real:` simulator, spec 001 FR-031). The renderer has no bundler, but a shared module with **no imports** (like `redact.ts`) can load as a plain script from `../shared/<name>.js` after `exports-shim.js` (`self.exports={}`). Keep that global: tsc's CommonJS output reads its own exported constants back as `exports.NAME` at call time, so deleting `exports` after load makes every call fail (`redact()` then returns `[redaction failed]`). `test-liveact` fails if `redact.ts` gains an import. Reuse this instead of copying masking rules into `src/renderer`.

## Agent apps (checked behaviour)
- **Codex protocol types without a session** (2026-10-21, `real:` codex-cli 0.163.0, 0 credits). `codex app-server generate-ts --out <dir>` writes the app-server's TypeScript types (`v2/ThreadItem.ts`, `ServerNotification.ts`); no sign-in, no model call. Read them instead of guessing: e.g. `fileChange.changes[].kind` is an object `{type: 'add'|'delete'|'update', move_path}`, not a string, and `item/fileChange/patchUpdated` streams the patch while `item/fileChange/outputDelta` is no longer sent.
- **Edit tools stream their arguments** (2026-10-21, `read:` SDK typings, spec 005). Claude Code `stream_event` `content_block_start` (`tool_use`) + `input_json_delta`; Copilot `assistant.tool_call_delta` (ephemeral, `toolName` "when known", `inputDelta` is JSON text, or raw text for a custom tool such as `apply_patch`); Codex `item/fileChange/patchUpdated`. Copilot's `apply_patch` argument is one string in the `*** Begin Patch` format (`real:` argument types counted in local session logs, no content read). `src/adapters/edits.ts` handles all three.
- **Edit argument streams on real sessions** (2026-10-21, `real:` spec 005 T036, Claude Code 2.1.304, Copilot CLI 1.0.101 / SDK 1.0.22, codex-cli 0.163.0, 6 prompts). Claude Code and Copilot stream as typed (Copilot sends `toolName` with every `assistant.tool_call_delta`, plus a `toolType` field; `auto` chose `apply_patch` with raw patch text). **Codex does not send `item/fileChange/patchUpdated` by default**: `codex features list` shows `apply_patch_streaming_events` as *under development*, off; the whole patch comes with `item/started`. Codex's `fileChange` approval names no file (summary `write`). **Script pitfall:** the permission broker emits a pending request before it starts waiting, so a script that calls `resolvePermission` synchronously inside `onEvent` answers nothing and the turn hangs; answer on a later tick (`setTimeout`), like the UI. Script: `scripts/edit-stream-real.ts` (records event types and field names only).

- **Usage-limit signals per agent app** (2026-10-21, spec 068, `read:` SDK typings and docs only; no limit was hit for real). Claude Code: `rate_limit_event.rate_limit_info` with `status: 'rejected'`, `resetsAt` (seconds), `rateLimitType` (`five_hour`, `seven_day`, ...); `allowed_warning` is only a warning. Codex: a failed turn with `codexErrorInfo: 'UsageLimitExceeded'`, and the reset time only in the earlier `account/rateLimits/updated` (`primary`/`secondary` with `usedPercent`, `windowDurationMins`, `resetsAt`). Copilot: `session.error` with `errorType` `rate_limit` or `quota` and an `errorCode` (`quota_exceeded`, `session_quota_exceeded`; `billing_not_configured` is not a wait), no reset time on the error; `account.getQuota` (free) has `quotaSnapshots.premium_interactions.resetDate`. How to apply: map them in `src/adapters/usagelimit.ts`, `claudeMap.ts`, `codexMap.ts`, `map.ts`; replace the fixtures in `scripts/test-coffeebreak.ts` once a real run is recorded.
- **`test-mcp-agentstate` pins renderer text** (2026-10-21, spec 068). Each state rule row lists fragments of `src/renderer/app.js` that must still be there; changing a `setState` call in `onLiveEvent` (or the limit or status branches) fails that test until the row and `src/main/mcp/agentstate.ts` follow. Change the three together.

- **Copilot, MCP tools in Read-only** (2026-10-20, `real:`, spec 044). A tool its server marks `readOnlyHint: true` runs without a permission request; the same tool without the hint arrives as kind `mcp` and Read-only denies it. Claude Code and Codex send every MCP call to the broker as `mcp` (`read:`).
- **Copilot SDK RPC methods always exist** (2026-10-21, `read:` SDK 1.0.22 `dist/generated/rpc.js`, PR #473). The generated `session.rpc.*` client defines every method whatever the runtime supports, so `typeof rpc.mcp.restartServer === 'function'` never detects an older runtime. Call it and fall back only on JSON-RPC MethodNotFound (`code === -32601`, or a message starting "Unhandled method", as the SDK's own `connect` check reads it): `isMethodNotFound` in `src/adapters/copilot.ts`.
- **Copilot starts MCP servers with the first message** (2026-10-21, `real:` SDK/runtime 1.0.22, Linux, spec 058 T060). Through our adapter no server starts and no `session.mcp_server_status_changed` arrives for 30 s after `createSession` (or a resume); they start within about 60 ms of the first `send`. `rpc.mcp.list()` may start them earlier ("cache misses may start and wait"), which is probably why spec 019's probe saw them at once. So do not expect a server list before the first message, and never test MCP start-up without sending one. Also: `resumeSession` of a session that never had a message fails "Session not found" (nothing was saved); use `sessionId` (resume if it exists, else create) as `ensureLive` does. SDK errors read "Request <method> failed with message: <reason>": strip the prefix before showing it (`sdkErrorText`).
- **Copilot remote control outside a GitHub repository** (2026-10-20, `real:`, spec 054): `remote.enable` answers `started: false` with no error and no URL. Treat that as "not started".
- **In a simulator driver, `bridge` in `js()` is the REAL preload API** (2026-10-22, `real:` spec 043 T016: a probe printed `bridge===window.agentDurbar` true and `typeof SIM` "undefined"). A page expression from a driver (`H.js`, `executeJavaScript`) does not see `app.js`'s `const bridge` (the simulator's); the name resolves to the contextBridge API, so `bridge.generateProfile(...)` there runs main's real `profiles:generate` and spends a real prompt even under `DURBAR_SIM` (main's IPC stays live in simulator mode). How to apply: never call `bridge.*` or `window.agentDurbar.*` from a driver; drive the UI, or hand a module a fake through its own `init`. The frozen API also ignores plain assignment silently (use `Object.defineProperty` on an `Object.create` copy). This cost 3 extra haiku prompts, plus 3 cut off mid-way.
- **Copilot theme maker replies** (2026-10-20, `real:`, spec 040): Copilot's `auto` wrote colour token names without the leading `--`; the parser accepts both.
- **Models copy the form of the defaults you show them** (2026-10-22, `real:` Claude haiku, spec 070 FR-031). The theme prompt asks for hex but lists each token's default; haiku answered `transparent` and `rgb(251 236 240 / .93)` exactly for the two tokens whose defaults have those forms. How to apply: a parser of model output accepts every form the prompt itself shows (or the prompt shows only the form it wants).

- **Copilot windows, prices and caps** (2026-10-20, `real:` Copilot Pro, spec 030 / 013):
  - **Windows:** the runtime's window (`usage_info.tokenLimit`) is the prompt budget, not `max_context_window_tokens`. `gpt-6-luna` 272k (1M listed), long tier 872k; `mai-code-1.1-flash` 128k.
  - **Prices:** `tokenPrices` are AI credits per `batchSize` tokens, and bills match exactly. Long-tier prices are not charged below the default window.
  - **Cost trap:** the prompt cache lives 5 minutes. A "tiny" prompt in a 125k-token session cost 15.7 credits after the cache expired, because it was written again and compacted. Keep paid probes inside 5 minutes, or on a model with a big window.
  - **Caps:** `maxAiCredits` is checked when a session is created or resumed, not before each turn. A running session went past its cap without any `limit` event. - **winget.exe cannot be `stat`ed from Node** (2026-10-21, `read:` npm/node-which#157, spec 060 FR-010; not seen on a Windows PC). Windows puts `winget.exe` (and Store apps such as a Store PowerShell 7) in `%LOCALAPPDATA%\Microsoft\WindowsApps` as *App Execution Aliases*: `fs.statSync` throws EACCES on them, `lstat` and `access` work, and only CreateProcess follows them. A `stat().isFile()` check therefore says "not there", and `realpath` leads into `C:\Program Files\WindowsApps`, which users cannot run. Use `statIsFile` from `src/adapters/detect.ts` (falls back to `lstat` only in that folder) and run an alias by its own path (`isAppAlias`).
- **Vendor install scripts on Windows** (2026-10-20, `real:` GitHub runners, spec 060 T060). (1) OpenAI's `install.ps1` calls `tar -xzf C:\...`.
