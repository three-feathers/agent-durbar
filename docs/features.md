# Features

Everything Agent Durbar can do, in detail. Moved out of the [README](../README.md) on 2026-10-31 so the README stays short (spec 021 FR-065); the text is unchanged except for its links.

## What you can do

**The office**
- Every agent is a person at a desk in its folder's room. You see at a glance who is idle, working, thinking, waiting for you or in trouble. A working agent whose last tool calls failed in a row says **Failing** (its door sign, with a lightning icon, in the amber trouble colours); one whose agent app is retrying a failed model call says **Retrying** with the attempt and a short reason (*Retrying (attempt 3 of 10) – servers busy (HTTP 529)*), and *Gave up after 4 retries – rate limit* when the retries run out (spec 034; read from each app's documented events, not yet seen on a real session). While an agent app compacts (summarises) a long conversation the card says **Compacting** with *Compacting the conversation…*, the chat shows a line where history was summarised (or *Older messages dropped…* when an app only trims), and the context ring says it too ([desk and chat](screenshots/015-compacting-office-1440x900.png), [chat](screenshots/015-compacting-chat-1440x900.png); at 1280x800: [desk](screenshots/015-compacting-office-1280x800.png), [chat](screenshots/015-compacting-chat-1280x800.png)); after a compaction whose new size the app does not report, the ring waits for the next message instead of showing the old figure (spec 015; Claude Code and Codex are read from their documented messages, Copilot's compaction was seen on a real account, none of the new Claude, Codex or truncation paths on a real session). A card in an Allow all folder says **Allow all**, and hovering a card tells when it last did something.
- 10-15 agents stay readable on one 1440x900 or 1280x800 screen, and the desks get denser on their own. Checked with 15 real Copilot sessions at once (Linux, 2026-10-21): no overlap or clipping at either size. With **few agents the desks grow** (up to about 2.5x, the largest size that fits without scrolling) and show more: the full title on two lines, up to 8 lines of the agent's thinking or reply as it streams (newest at the bottom), the start of the last reply when it is done, and tokens and cost. They get smaller as agents are added, down to the usual densities; the size is the largest that fits, so a new row of desks can make it drop several sizes at once. Grown desks come before the side panel below. A wide grown desk (one agent, or a row with spare width) uses the width for **more information, not longer lines**: beside the stream it shows the start of the last reply (masked) and the tool, usage, context and time on task, in columns of at most about 85 characters a line, and folds back to one column as it gets narrower. Simulator-checked from 1024x700 to 2560x1440 ([1 agent](screenshots/001-fill-1-1440x900.png), [1 agent at 1920x1080](screenshots/001-fill-1-1920x1080.png), [4 agents](screenshots/001-fill-4-1440x900.png), [6 agents](screenshots/001-fill-6-1440x900.png)); not yet watched on real sessions.
- **Finished agents rest in the lounge** when others still work in their folder, so the busy desks get the width: a lounge corner at the end of the desk row (about 300 px for five). An agent that finished in the last 10 minutes sits on the couch, its name on the cushion, with a speech bubble saying what it did last (the start of its reply on up to three lines, secrets masked); an older one naps in a bunk bed and dreams of its last work (with several sleepers the dreams take turns; "+N asleep" past four). Each is the same character as at its desk. Hover or keyboard focus opens a small card beside the lounge; a click or Enter opens the chat as before. Waiting, Error, Limit and Paused agents never rest, and a folder where everyone is finished stays as it is. Turn it off in Settings > Detail level (*Finished agents rest in the lounge*). Simulator-checked at 1440x900 and 1280x800 ([2 working, 2 on the couch, 3 asleep](screenshots/001-shutters-1440x900.png)); not yet watched on real sessions.
- **A finished agent's reply is marked "New" until you have seen it** (spec 001 FR-170..FR-177, spec 005 FR-176, FR-177, issue 691). When an agent finishes while you are not looking at its chat (you are in the office, in another chat, in the Browser tab or in the Notes drawer, or the window is hidden), its desk, list row and chat-strip item get a small **New** badge with a dot, and the desk a soft green glow, and the person zooms gently (a desk that needs you glows amber-orange and its person pulses more, and that wins; reduced motion: static glow only; spec 001 FR-178); the desk's accessible name adds "new reply not read yet" and one polite announcement says "<name> finished. New reply." (once, not per streaming update; none for a hidden folder or floor, which keeps its marker for when it is shown again). It is a marker beside the state, not a state: the Done count, sort, filters, attention and permissions are as before, and an unread agent **stays on its desk** instead of going to the couch. It clears only when its chat is shown (opening the chat, or coming back to the Chat tab, closing the Notes drawer or bringing the window back while it is open) or with **Mark as read** in the card menu (right-click, or Shift+F10 / the Menu key on a focused desk or list row); closing the chat or returning to the office does not clear it, and once read the agent follows the couch rule above. The badge pulses once when it appears, and only if your system allows motion. **It is not kept across a restart** (like the chat itself): after a restart or reload nothing is marked. Simulator-checked at 1440x900 and 1280x800 (all 15 unread fit; `npm run check:ui -- --only check-unread`); not watched on real sessions. ![Two unread replies](screenshots/001-unread-1440x900.png)
- **A status pill says what it hides** (spec 001 FR-180, FR-181, issue 790): the counts in the top bar (Working, Waiting, Idle, Error, Done) are also filters. While one is on, the office and List show **Showing only idle · 3 hidden · Show all** (Show all is the same toggle as pressing the pill again; a screen reader is told once; a hidden session that needs you is named, for example *3 hidden (1 needs you)*), so a finished session the filter hides does not look lost. The chat strip still lists every open chat. Checked on the simulator only (`npm run check:ui -- --only check-status-filter`, both sizes); the reported case is not confirmed on a real run.
- **Cabin doors with meeting-room signs** (spec 017, owner request): each session is an office cabin. While the agent works, must not be disturbed or is away, its door is closed **in place of the desk**, with the agent's photo and a sign like the one beside a meeting-room door: **Busy**, **Thinking**, **Retrying**, **Compacting** (the agent app summarises its conversation), **Failing** (tool calls keep failing), **In a meeting** (one of its helpers works), **Do not disturb** (paused, or on a coffee break that resumes by itself), **Away** (session ended). An agent **waiting for you** (a question or a permission) stands in front of its closed door and waves, under the **Waiting for you** sign; at Durbar's **spending limit** it holds out an empty wallet under **Limit reached** (the same props on its figure in the lobby: waving at the Boss, the wallet at the Bank). When its work is done the door stands open with a **Done** tag and you see the desk as before; a free agent shows **Available**; an agent with an error keeps its door open with **Alert** and small flames on the desk. The desk's status pill keeps its plain word (Working, Thinking, Retrying, Failing, Error, ...) as before; on the card, mini and micro desks the door's sign is its icon only, with its full word in its tooltip (a door you closed also shows its word, DND, and the desk's accessible name says it). A click on a closed door opens the chat. **Close a door yourself** with the small door button on a desk (keyboard too, `aria-pressed`): the agent is then **Do not disturb**, its scheduled prompts wait at the door (never sent, never lost, kept across a restart) and remote control goes off; opening the door lists them (masked) and asks whether to **Send all** (in order, the next one when the agent is free, through the schedules, so Pause all and each schedule's own limit still apply) or **Discard** them (Keep closed is the default; [screenshot](screenshots/017-held-dialog-1440x900.png)); an open door that still holds some says **Available · N held**, and a door that cannot hold more says so instead of dropping a prompt quietly. If remote control cannot be turned off, the door stays open and says why; while a door you closed is shut, turning remote control on is refused with an **Open the door** button. Messages typed remotely on github.com or claude.ai go straight into the agent app, so Durbar cannot hold them; it turns remote control off instead. Every animation is still with reduced motion or in Serious mode. Settings > Detail level > **Office layout** switches between **Office with cabins** (the default) and **Open office**, the desks as they were before the cabins ([screenshot](screenshots/017-open-office-1440x900.png), [at 1280x800](screenshots/017-open-office-1280x800.png), [the setting](screenshots/017-office-layout-1440x900.png)); switching to Open office with a door you closed asks first and opens it (Send all or Discard what it holds), so nothing held is hidden. Simulator-checked at 1440x900 and 1280x800 in all six themes ([screenshot](screenshots/017-signs-1440x900.png)); not yet watched on real sessions.
- **Live activity on the desks:** while an agent works you see what it is doing without opening the chat: the latest sentence of its thinking, the tool it runs ("Reading src/x.ts", "Running npm test") or the reply as it streams. With few agents across, a panel beside each desk shows a few lines; in a busy office it takes the line under the agent's name (the name stays). At most 4 updates a second, nothing moves, and secrets are masked like everywhere else. Settings > General > *Live activity on desks* turns it off. Simulator-checked ([sparse](screenshots/001-live-activity-side-1440x900.png), [busy](screenshots/001-live-activity-dense-1440x900.png)); not yet watched on a real session.
- **Boss, Bank and Postbox in the lobby** (who waits, what is scheduled, who is where): an agent with a **question or a permission** for you gets up and walks to the **Boss** in the middle of the lobby and queues there, first come first served, with a small **?** or **key** on its figure; the Boss shows the longest wait ("12 min") and its desk an empty chair with *Went to see the boss*. Click a figure to open its chat at the request; once you answer, it walks back. An agent at **your spending limit** waits at the **Bank** (click: the chat with the raise-limit card); usage-window limits of the agent apps still go to the coffee corner. The **Postbox** shows the next three scheduled runs ("09:14 · mcp-swiss · Morning summary"), how many are still due today and a flag for a missed or failed run; when a schedule fires, a letter flies to that desk (not with reduced motion). Click it for Settings > Schedules. Every lobby place says **who** is there and what they do ("Ada · npm test"; initials when names do not fit, "+N" lists everyone), and room headers count in words ("4 working"). Theme words rename the three tiles (Durbar: Diwan-e-Khas, Khazana, Dak ghar). Simulator-checked at 1440x900 and 1280x800 ([office](screenshots/001-lobby-15-1440x900.png), [1280x800](screenshots/001-lobby-15-1280x800.png), [few agents](screenshots/001-lobby-3-1440x900.png), [Retro](screenshots/001-lobby-15-1440x900-retro.png)); not yet seen on a real session or on a Mac or Windows PC.
- **Sub-agents (helpers) sit under the agent that started them, and show what they do when the office has room** (spec 001, issue 697). With few agents, while the parent desks can stay at least 1.4x grown, a helper is a **card with labelled lines** instead of a name-and-status tile: **Task**, what it does **Now** (the tool, its intent or *Thinking*), its **Result** when it is done or **Failed** with the error, and a line of facts (model, time, tool calls, tokens); the full card when there is room, name plus one line when there is less, the small tile as before when there is not even that (so 15 agents look as they did). What the agent app did not send reads *Task not reported*, *Result not reported* or *No activity reported yet*, never another field: OpenAI Codex sends no result for a helper, so its card says so. Click a card for the helper's read-only activity. **Task, Result and Failed text is always on the office floor when there is room** (masked for secret shapes like everywhere else and cut to 240 characters); only the **Now** line follows *Live activity on desks*. There is no setting to hide the rest, and none is planned (owner decision, 2026-10-25), so mind screen sharing: a result can show file contents, names or other text that is not a token. Simulator-checked ([two agents, 1440x900](screenshots/001-helpers-2-1440x900.png) and [1280x800](screenshots/001-helpers-2-1280x800.png); [three agents, 1440x900](screenshots/001-helpers-3-1440x900.png) and [1280x800](screenshots/001-helpers-3-1280x800.png)); not run on a real session (what each agent app sends is read from the adapters and earlier captures, not seen live for this).
- Agents show how they are doing: heavy, monster, ambulance, room sirens. Main agents walk to a **place** in a shared lobby for the tool they use.
- **Coffee break** (spec 068): when an agent's usage limit is used up (a Claude Code or Codex plan window, Copilot's premium requests or rate limit), it waits in the lobby's **coffee corner** with a cup instead of showing an error. Its card says *Coffee break — resumes at 4:24 PM* when the agent app says when the limit resets. The spending limit you set in Durbar sends the agent to the **Bank** instead (*Limit reached — until you raise the limit*). When the limit resets it comes back and sends one message to continue, but only by itself when that costs nothing extra (a plan or rate window); a quota that may lead to paid usage, or *Always ask me* in Settings, asks first. It never resumes past your spending limit or after a restart, and never checks on its own whether a limit has reset ([screenshot](screenshots/068-coffee-office-15-1440x900.png)). Click an agent in the coffee corner (or press Enter on it) to open its chat, where a bar says how long the break lasts (*On a coffee break · back in 4 min*) and offers **Retry now**: one message now instead of waiting (right-click or Shift+F10 on the corner's entry offers the same; [screenshot](screenshots/068-coffee-bar-1440x900.png)). Simulator and unit tests only: no real session has been run into a limit, so the limit messages and reset times of the agent apps are read from their docs and may differ.
- **Floors** group rooms and can be switched off. With two or more floors on, the office shows **one floor at a time**, at the best size for that floor's agents (the lobby is on every floor), and a **lift panel** at the right edge has one numbered button per floor that is on (the name is in its tooltip). A button of another floor carries a **badge** with the number of agents there that need you (waiting, error, limit reached, a New reply; the words are in its tooltip and accessible name). **All** at the top of the lift shows **every floor on one screen** again, as before, with one size for all of them; the choice is remembered. The lift is one Tab stop: Up/Down, Home/End, Enter or Space. **PageDown** goes to the next floor that is on, **PageUp** to the previous one (**Fn+Down / Fn+Up** on a Mac laptop), and a floor taller than the window scrolls first with the same keys (it changes floor only from its edge); in **All** they only scroll. The pills, the inbox and the usage total still count the whole building. This is [spec 092](../specs/092-floors-as-places/spec.md) phases 1 and 2: the slide between floors and "open an agent, land on its floor" are not built yet (a floor change is instant, and a chat opened from another floor returns to the floor you were on); tried on the simulator, not on a real Mac or Windows keyboard nor with a screen reader. With two or more floors, right-click a folder (or its **⋯**) and choose **Move to floor ▸** to send the whole folder, agents included, to another floor, with **Undo**. A **List** view is there when you want rows instead of desks: agent app, role, folder, task, last activity and cost columns, sortable, with J/K to move; the columns follow their content (a cut cell shows its full text on hover) and a narrow window drops Role, then Folder, instead of scrolling sideways.
- A room's **⋯** menu offers New session, Schedules, Rename, MCP extras, Cost, Move to floor, Hide and **Remove folder**. The folder name always keeps at least 8 characters: in a tight header the pencil, the schedule chip, MCP, the floor tag and the cost give way one at a time, and are all in that menu. You can also rename a folder in place: the pencil after its name (or **F2** on its door) edits the name where it is.

**Chat**
- Click an agent to open a full-screen chat. All the other agents stay in a slim strip.
- You see its thinking, tool calls and replies as they stream in, with Markdown and copy buttons. An open tool call shows the whole command (with Copy), how long it took and its output; a Claude Code or Codex edit request has a **Show the change** diff (a Codex request with no known file says "Codex did not say which file").
- **File edits show up while the agent writes them:** the moment an agent starts changing a file, the chat shows "Editing app.js" with its folder and "+12 −3", and the change itself as a compact diff (12 lines, then **Show all**) that grows as the agent writes it; several files are listed one by one. The line under the chat names what runs now ("Editing app.js · 12s", or "Waiting for your OK" while a permission card waits). An edit that was refused or failed says so ("Could not edit app.js"; Simple: "Not changed"). In Simple the words are plain ("Changing 2 files") and the diff is behind **See what changes**. Secrets in a diff are masked (by the adapter, then in main with the session's MCP secret values too). Claude Code and Copilot stream the edit, so the row appears before the tool runs (checked on real sessions, Linux); Codex sends the whole change at once, so its row appears when the edit starts ([spec 005](../specs/005-chat-fullscreen-and-agent-strip/spec.md), [screenshot](screenshots/005-edit-expert-1440x900.png)).
- Attach files and images by picking, dropping or pasting.
- **A browser in every chat** (spec 080, issue [#556](https://github.com/three-feathers/agent-durbar/issues/556)): each chat has **Chat | Browser** tabs. The Browser tab has an address field, Back, Forward, Reload and Stop, a **Sound** toggle (sound starts off) and **Open in system browser**. Each session gets its own private, in-memory profile: cookies, storage and cache are never shared with another session and are wiped when the session ends, is removed or its folder is removed. A click on an `http` or `https` link in a chat opens it in that session's Browser tab (Ctrl+click, or ⌘+click on a Mac, and the link's right-click menu open it in your usual browser; *Settings > Open chat links in* changes the plain click). Only `http` and `https` addresses open; `file:`, `javascript:`, other schemes and addresses with a user name and password are refused with a reason. **Page tabs** (spec 080 US6, issue [#910](https://github.com/three-feathers/agent-durbar/issues/910)): each session's browser holds up to 10 tabs, in a strip above the address bar ([screenshot](screenshots/080-browser-tabs-1440x900.png), [1280x800](screenshots/080-browser-tabs-1280x800.png)); **+** or Ctrl+T (⌘T) opens one, its **x**, Ctrl+W (⌘W) or Delete in the strip closes one, Ctrl+Tab and Ctrl+Shift+Tab switch. The bar's **⋯** menu has **Open chat links in a new tab** (off by default, one setting for every session): with it on, a chat link opens in a new tab next to the one you are reading, and a link a tab already shows brings that tab to the front instead of opening it twice; the link's right-click menu has **Open in a new tab** either way. A page's own *open in a new tab* links open a tab of the same session too (only `http`/`https` from the page's own site, at most 5 per page load). The session's tabs share its private profile, so a sign-in in one tab holds in the others, and all of it is wiped when the session ends. Linux and the simulator only so far; see Known limits.
- Questions an agent asks you appear as a card with its choices, an "Other" answer and Skip. The whole question, every choice and its description are shown in full; Enter in the "Other" box sends your answer (Shift+Enter adds a line). While a question waits and its card is scrolled out of view, the bar above the message box shows it; a short one can be answered right there (its choices, an "Other" box and Skip), a longer one has **Show question**. Several context compactions in a row are one line that counts them ("Context compacted 4 times · last 10:21").
- **Needs you:** one inbox of every agent waiting for you, oldest first with how long each has waited. Open it with **I**, **Ctrl+Shift+A** (also from a text box) or **Ctrl+A** when the cursor is not in a text box or the chat log (there Ctrl+A still selects all). While Durbar is in the background the window title ("(3) Agent Durbar"), the app icon and one notification tell you (Settings > Notifications turns it off; it shows only the agent's name and a short summary). In a waiting chat, **Alt+A** allows once, **Alt+S** allows for the session, **Alt+D** denies and **Alt+N** goes to the next agent; **?** lists every shortcut.
- **Under the message box**, as in VS Code, one compact row sets how the next message runs: the profile, the mode (*Read-only*, *Ask first*, *Allow all* in red), the model's name (its menu holds the effort and the context window choices that model has), a small **context ring** coloured by how full the window is (green, amber from 70%, red above 90%; hover for "Context 55% of 1M"; click for a token summary with one bar per type the agent app reports: system instructions, tool definitions, chat messages, other; Claude Code and Codex report only a total, and the summary says so; **Compact** is there too), **MCP 12/16** (servers on out of all servers for this chat; it opens the server list), and attach file or image. In a narrow window what does not fit goes under **⋯**; the mode always stays in view. Simple shows the mode, memory and attachments ([screenshot](screenshots/005-composer-expert-light-1440x900.png), [token summary](screenshots/005-composer-ctxsummary-1440x900.png), [at 1280x800](screenshots/005-composer-ctxsummary-1280x800.png)).
- **Type `/` for the folder's skills and commands** (spec 073): at the start of a word in the message box, a list shows the skills, commands and prompt files of this agent app in the folder or workspace, then your own (user level), then a short allow list of the app's built-ins where typing them really runs them (Claude Code only: `compact`, `context`, `cost`, `init`, `review`, `security-review`; a built-in a later Claude Code adds is never offered by default). Each row has the name, a one-line description and where it comes from; typing filters, arrow keys move, Tab or Enter put it in the box, Esc closes the list. Places: Claude Code `.claude/skills`, `.claude/commands` (and `~/.claude`); Copilot `.github/skills`, `.claude/skills`, `.agents/skills` (and `$COPILOT_HOME/skills`, default `~/.copilot/skills`, and `~/.agents/skills`); Codex `.agents/skills` (and `~/.agents/skills`, `~/.codex/skills`, `~/.codex/prompts` as `/prompts:<name>`). Every app also lists VS Code prompt files: the folder's `.github/prompts/*.prompt.md` and your VS Code user prompts (`Code/User/prompts` in `%APPDATA%`, `~/Library/Application Support` or `~/.config`); Durbar fills their `${input:name}` variables from your words (in order, or `name=value`). Claude Code and Copilot do not load these files in Durbar's sessions (checked), and Codex's app-server does not expand a typed `/name`, so for a folder or user entry Durbar sends that file's text with your words as its arguments, and the chat says so ([screenshot](screenshots/073-slash-1440x900.png)).
- **Send / Stop:** one button inside the message box. It is **Send** while the agent is idle and **Stop** (with a spinner beside it) while a reply runs; type during a reply and Send shows beside Stop. **End** a session from More, or Stop and End from the agent's card menu ([screenshot](screenshots/005-card-menu-stop-end-1440x900.png)).
- **A message box that grows** (spec 005, issue #592): long prompts grow the box up to 40% of the chat (then it scrolls), and the transcript always keeps a few lines visible. Drag the thin handle on its top edge to choose a height (or focus it and use the arrow keys); double-click it, or press Enter on it, to let it grow with your text again. The chosen height is remembered for the whole app on this computer.

**Sessions and folders**
- One session per folder or `.code-workspace` file, or several per folder (**+ New** in a chat's header, or **+ New session** under More).
- The top bar is one row: **+ Folder** and **+ Workspace** come first, right after the app name (Ctrl+O and Ctrl+Shift+O; on a Mac also **File > Add Folder…** ⌘O and **Add VS Code Workspace…** ⇧⌘O), the **Defaults** chip (for example "Copilot · Read-only · Auto") sets the agent app, permission mode and model for new sessions, and **Manage folders** sits next to the folder filter. On narrower screens the status counters show a dot and a number: hover one, or Tab to it, and a tooltip appears at once (no system delay, the same on every OS) naming the state and the count, for example *Idle · 7 agents idle or paused. Click to show only these.* (*Click to show all.* while that filter is on); Escape hides it, and it never covers the count it explains (spec 001 FR-187, issue 875; the schedules, Needs you and usage chips still use the system tooltip; checked on the simulator only, [picture](screenshots/001-status-tooltip-1440x900.png)).
- **Create a folder from + Folder** ([spec 093](../specs/093-create-folder/spec.md), issue [#805](https://github.com/three-feathers/agent-durbar/issues/805); phases 1 and 2): **+ Folder** (and the welcome screen's add button) asks *Add existing folder…* (first, so Enter keeps today's behaviour), *Clone a repository…*, *New repository…* (an empty folder with `git init`, on this computer only: no remote, no account) or *Empty folder…* ([screenshot](screenshots/093-choice-1440x900.png)). You pick the place in the system picker (it opens where you created the last one) and type a name. Durbar refuses a name that would not work on every computer (`/` or `\`, `..`, `CON` and the other Windows device names, a trailing dot or space, a leading `-`, `.git`, `< > : " | ? *`) or that already exists there, says why and keeps what you typed ([screenshot](screenshots/093-name-refused-1440x900.png)). The new folder joins the office like an added one, in the top bar's mode (Read-only by default; *Allow all* asks first). **Ctrl+O**, **File > Add Folder…** and the palette's *Add folder* still open the system picker directly; **File > New Folder…** (Mac) and the palette's *Clone a repository*, *New repository* and *New empty folder* go straight to creating. Without git installed, *Clone* and *New repository* say so and *Empty folder* still works. **Clone a repository…** takes an `https://` address or an ssh one (`git@github.com:owner/repo.git` or `ssh://…`) and refuses anything else (`file://`, `ext::`, `git://`, `http://`, local paths, a leading `-`, a password in the address) with the reason ([screenshot](screenshots/093-clone-url-refused-1440x900.png)); the name starts as the repository's (`shop` from `…/shop.git`). A progress dialog shows git's phase, percent and last lines, the time so far and **Cancel** (Escape too): Cancel ends the clone and removes the half-made folder ("Cancelled. Nothing was kept.") ([screenshot](screenshots/093-clone-progress-1440x900.png)). Your own git credentials do the sign-in (your credential helper, your ssh agent); Durbar never asks for, sees or keeps a password, so a repository that needs one you have not set up fails with a plain message. An ssh host you never connected to fails with "Connect once with ssh in a terminal". If the top bar is in *Allow all*, the confirmation also says "This code comes from <host>; agents can run it without asking." ([screenshot](screenshots/093-clone-allow-1440x900.png)).
- After a restart, each folder **continues its open sessions** (up to 6 per folder, each resumed when you open its chat or send it a message), and Durbar **remembers where you were**: the window's place and size (back on a screen it fits, else 1440x900), Office or List, the folder filter and the open chat.
- After more than 30 minutes closed, a **Since you were away** strip says how long it was and which scheduled prompts did not run, with **Run missed now** for each.
- **After a crash**, one card says "N sessions were interrupted" (the ones that were mid-reply when Durbar stopped unexpectedly: a crash, a kill or a power loss) with **Resume all**, **Pick…** and **Dismiss** ([screenshot](screenshots/006-crash-card-1440x900.png)). Resuming reopens each session under its own mode and cap and shows its earlier conversation; it sends no prompt, and the reply that was being written is lost, so say "continue". Nothing resumes by itself and the last prompt is never sent again. The dialog reads the agent app's server list again when it opens (at most once a minute, and only when every server is already running), and **Refresh** does it on demand at any time (Copilot and Claude Code; Codex cannot report its list again, and the dialog says so). Checked on the simulator only, not on a real account.
  - **Sign in for Claude Code servers:** a Claude Code row that reads *Needs sign-in* has the same **Sign in**, two-step open and **Cancel**: Durbar asks the running Claude Code to start its own sign-in for that one server (it runs discovery and its own `127.0.0.1` callback; Durbar never sees a code or token and sends no callback address), and keeps the page for the 5 minutes Claude Code waits, minus a margin. Durbar never runs `claude mcp login` itself. The row keeps **Restart**: after a sign-in finished elsewhere (a terminal, or the browser after **Cancel**) it makes the running session pick it up, and opening the dialog or coming back to the window within 5 minutes of an attempt reads the list once. *How to sign in from a terminal* says: run `claude mcp login <name>`, finish in your browser (this works only for a server in Claude Code's own settings), then press **Restart** on the row. A server in Claude Code's own list that has `oauth` settings (`clientId`, `callbackPort`, `authServerMetadataUrl`, `scopes`) gets those, and only those, in Durbar's copy (never a client secret). The "different site" line compares with the agent app's own copy of the server (an earlier build could compare with a Copilot server of the same name). The request Durbar uses (`mcp_authenticate`) is not in Claude Code's documentation and was read from version 2.1.304 only; on another version, or with no answer in 30 seconds, the terminal steps show. Not checked on a real account yet: simulator and test harnesses only ([spec 058](../specs/058-mcp-session-controls/spec.md) FR-175, FR-176, FR-180..FR-186; real check T106 pending; Codex rows follow in a later change);
  - when a server asks you for input (a small form, or a sign-in page), the chat shows it with **Submit / Decline / Cancel**; a page opens in your browser only after you click, and only if it is https (simulator and test harnesses only so far, not yet tried with a real server).
- **Tools** shows what each agent used, for *This session* and *All time*, and a **Cost** tab with each folder's ≈ money, AIU, Claude estimate, tokens and calls (the same *This session* or *All time*, with the start date under it), with **Copy as CSV**. Clicking a room's cost opens it.
- **Activity** (Tools > Activity) is a local log for a team lead: every answer to a permission request, every automatic approval (Allow all or a session permission), every mode or spending-limit change, and every MCP restart (spec 058), with time, agent, folder, agent app and mode. It keeps the newest 5000 rows on this computer, holds actions and decisions only (never prompts, replies or file contents), and exports to CSV or JSON. Claude Code and Codex in Allow all approve inside their own process, so their automatic approvals are not listed (Copilot's are).
