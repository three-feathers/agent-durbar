# Changelog

Agent Durbar is an alpha. Builds are unsigned and have only been run by hand on Linux (see "Honest limits"). Each entry names the spec that describes the behavior and how it was checked.

## Unreleased (on `main`, after the alpha.4 tag)

- **Claude sessions load no Claude settings files (spec 012 T027, issue #46; owner decision Q8).** Mode options for the future Claude adapter set `settingSources: []` and `strictMcpConfig: true` in every mode, trusted folder or not, so a repo's or user's Claude settings and MCP servers cannot approve tools before Durbar asks. A repo's own `.claude` hooks and agents do not run (known gap, T083); the repo's `CLAUDE.md` will be passed as an appended system prompt by the Claude adapter (T045). Unit tests only; not wired to a real Claude yet.

- **Secrets are redacted from the debug log (spec 012 T051, issue #59).** Every `DURBAR_LOG` line now goes through one sink that hides environment secrets (also JSON- and URL-encoded) and token-like strings (GitHub, OpenAI/Anthropic keys, Bearer, JWT, AWS keys, URL credentials) before it is written. Unit tests with planted secrets, 0 AIU.

- **Mixed-kind simulator and capability gating (spec 012 T018, issue #38).** `simkinds=mixed` in the simulator shows Claude-like, Codex-like and a minimal kind next to Copilot; room and header buttons, the mode chip, mode lists and the Permissions selects follow each kind's capabilities and never widen. No visible change with Copilot alone. Simulator only, 0 AIU.

- **Agent kind picker (spec 012 T017, issue #37).** With more than one kind of agent, the toolbar and the New session dialog get an agent-kind select before Permissions; kinds that are not installed or too old are disabled and explained in "About agent kinds". Controls an adapter cannot support are hidden. No visible change while only Copilot exists. Simulator and unit tests, 0 AIU.

- **Codex permission-mode and approval mapping (spec 012 T022, issue #41).** A pure module that turns Read-only / Ask first / Allow all into Codex sandbox and approval settings and maps its approval requests and answers; a missing or unknown mode always declines. Not wired yet, no user-visible change. Unit tests, 0 AIU.

- **Claude Code permission-mode and tool mapping (spec 012 T021, issue #40).** A pure module that turns Read-only / Ask first / Allow all into Claude Agent SDK options and decides which tools each mode allows; Read-only denies every non-read tool (MCP included), and an unknown or missing mode falls back to Read-only. No SDK dependency, not wired yet, no user-visible change. Unit tests, 0 AIU.

- **Codex event mapper (spec 012 T024, issue #43).** A pure mapper from Codex app-server notifications to Durbar's events (messages, thinking, commands, file changes, MCP tools, sub-agents, token usage, failures), tested against synthetic fixtures. Not wired yet, no user-visible change, 0 AIU.

- **Claude Code event mapper (spec 012 T023, issue #42).** A pure mapper from Claude Agent SDK stream messages to Durbar's events (text, thinking, tools, MCP tools parsed against the init server list, sub-agents closed exactly once, token usage, cost estimate as per-result deltas, errors), tested against synthetic fixtures. No SDK dependency, not wired yet, no user-visible change, 0 AIU.

- **Codex JSON-RPC client (spec 012 T042, issue #50).** A line-delimited JSON-RPC client for `codex app-server` over a child process (argv only, no shell): framing, ids, timeouts, server requests, malformed and oversize lines, child exit and a SIGTERM-then-SIGKILL close. Tested on a fake child process; not wired yet, no user-visible change, 0 AIU.

- **Docs for the Claude Code and Codex groundwork (spec 012 T019).** The README has an *Agents and adapters* table: Copilot is supported; Claude Code and Codex are planned and marked simulator/fixtures only, with no adapter and nothing run on a real account.

- **Copilot passes the adapter contract (spec 012 T016, issue #36; spec 002 T020).** The contract suite and a replay of the recorded sessions now run on the Copilot adapter through a fake SDK client. Test code only, 0 AIU.

- **Adapter contract suite (spec 012 T015, issue #35).** A fake adapter and a shared contract every adapter must pass (events, permissions, stop, capabilities), plus tests for the main-process rules that refuse settings an adapter cannot apply. No user-visible change. Unit tests, 0 AIU.

- **Agents are routed to their adapter (spec 012 T014, issue #34).** The main process now keeps one adapter per kind (only Copilot today) and routes each agent's calls to it; `listAdapters()` reports each adapter's status. A setting an adapter cannot apply to a live session is refused instead of silently saved. Copilot unchanged. Unit tests and the simulator, 0 AIU.

- **Saved folders can record their agent kind (spec 012 T013, issue #33).** A new optional `adapterId` per saved folder, never written for Copilot, so existing files stay byte-identical; read by the app since T014 (T013 itself changed only the store). Unit tests, 0 AIU.

- **Claude Code and Codex CLI detection (spec 012 T012, issue #32).** Pure code that finds the `claude` and `codex` commands (PATH, known folders, Windows npm shims through a guarded cmd.exe) and reads their version, without a shell; since T014 only the Copilot detector is used by the app (`adapters:list`), the `claude` and `codex` ones are not called yet. Unit tests, 0 AIU.

- **Adapter registry and descriptors (spec 012 T011, issue #31).** A pure list of the agents the app knows (only Copilot today), with what each can do and a way to check if it is installed; since T014 the app builds its adapter from it; no visible change. Unit tests, 0 AIU.

- **Adapter interface ready for more agents (spec 012 T010, issue #30).** The app now talks to every agent through one interface with declared capabilities; Copilot works exactly as before. Groundwork for Claude Code and Codex; simulator and unit tests, 0 AIU.

- **Custom places in the lobby (spec 024 delta, issue #115).** Add up to 3 places of your own, with a name and an icon from a fixed set, from the lobby or Settings > Places, and send MCP servers there. Rename keeps the mapping; delete sends the servers back to their default place. The lobby stays one row at 1440x900 and 1280x800. Simulator, unit tests and `scripts/shots-024-custom.js`, 0 AIU; not checked on a real session.

- **Settings > Places lists every folder's own MCP servers (spec 024 delta, issue #116).** Per-folder extras now get a row before any agent has used them, read by name only from the saved folders; choosing a place never switches a server on or trusts it.

- **One GitHub server in Settings > Places (spec 024 delta, issue #117).** `github` (your own server in `~/.copilot/mcp-config.json`) and Copilot's built-in `github-mcp-server` (the name its tool events carry) are one row, `github`, with the note "also github-mcp-server"; a place chosen there now applies to calls from both. Saving moves an old `github-mcp-server` entry to `github`. Simulator and unit tests (`test:places`, `scripts/shots-024.js`), 0 AIU; not checked on a real session.

- **Rooms show their worst agent (spec 034 delta, issue #135).** A room keeps its colour but gets a little darker when its worst agent is heavy (70-90% context) and clearly darker with a monster, an agent in Error or any trouble; a small red/blue siren blinks next to the room name (and on the door plate when it is closed) while the room has the ambulance or a fainted agent, and its label says "Alert: an agent needs help". Header text gets darker with the floor, and the folder path in every room header is a little darker (it was about 4.2:1, now 4.5:1 or more). Serious mode turns it off; reduced motion stops the blink. Simulator and unit tests, 0 AIU.

- **Agents show how they are doing (spec 034, issue #20).** An agent's figure gets heavier from 70% of its context window and turns into a grumpy green monster above 90% (time for a fresh session). Trouble gets a drawing: an ambulance by the desk when a session errors (one at a time, the latest error), a faint at the credit limit, tapping the desk after waiting 60 s for you, dizzy stars after 3 failed tool calls in a row. Card text is unchanged; the card's tooltip and accessible label name the state. **Settings > Agent mood > Serious mode** turns it all off; with reduced motion nothing moves. Simulator: `simwaitold=1`. Simulator and unit tests (`test:mood`, `scripts/shots-034.js`), 0 AIU; not checked on a real session.

- **Floors (spec 033, branch `033-floors`).** Group rooms into floors and switch a floor off: it leaves the office, the list, the filter, the strip and the lobby and is not counted in the status pills; its agents keep running (no alerts; what waits there is shown only as text on the floor's row in the Floors panel and Settings) and the office credit total still counts them. Top-bar *Floors n/m* panel and a *Floors* section in Settings with On/Off, Only, rename, reorder, delete, move folder and the floor for new folders. Simulator and unit tests only, 0 AI credits.
- **Usage totals kept across restarts (spec 011 FR-024..FR-030, issue #21).** The office chip and the folder totals now show the credits spent **since the last reset**, saved on this computer (`durbar-usage-totals.json`: numbers, folder names and a fingerprint of each folder's path, never prompts or paths); the tooltip also gives this run alone. Settings > Credit cap > *Usage totals* shows the figure and has **Reset usage totals** (with a confirmation; Tools > All time is not touched). "credits not reported" can now be seen in the simulator (`simunreported=<room>`). The multiplier estimate is left to spec 030. Simulator and unit tests (`test:usagedoc`, `scripts/shots-021.js`), 0 AIU; not checked on a real session.

### What's new

- **MCP servers (specs 019, 020).** The **Copilot CLI's own list** (`~/.copilot/mcp-config.json` plus the built-in GitHub server) is read live and is the primary, global source in Settings and in the Tools view, with call counts and the exact command or URL (no env or header values). Nothing to import. Extra servers that only this app passes to a session are stored **per folder or workspace** (room-header MCP button) with a trust prompt that shows the exact command; secrets stay encrypted with the OS store. Servers from the CLI list get no trust prompt (decided by Vikram, 2026-10-16). The old app-level list and its Import buttons are gone.
- **Tool usage (specs 019, 020).** The Tools view has **This session** and **All time**. All time is kept on disk (`durbar-tool-usage.json` in the app's userData folder) and survives restarts: per tool, per MCP server, per agent. Only tool names, server names, agent labels and counts are stored; never arguments, output, prompts or paths. A second tab shows models and the context window used per agent. **Reset all-time counts** clears it.
- **Credit caps (spec 011).** Optional AI-credit cap per session (runtime minimum 30), set in the new-session dialog or from the chat header chip, with a global default in Settings. Cards and the chat header show used/cap; it is a **soft** cap (one response can overshoot). When reached: **Limit reached**, then Add credits / Remove cap / Stop here. `[UNVERIFIED]` against a real exhausted cap (it costs real money); covered by fixtures and the simulator.
- **Permissions (specs 003, 018).** Change an agent's mode (Read-only, Ask first, Allow all) any time. The saved mode of each folder is **restored exactly** after a restart, *Allow all* included, with a visible *restored* note until you change it; switching to Allow all still asks for confirmation. (The alpha.2 build itself still labels the last mode *Allow edits*; it was renamed *Allow all* right after, see alpha.3.) *Approve for this session* grants never survive a restart. Shell grants cover the **exact command** unless you explicitly choose "any arguments" (never for shells, interpreters, `sudo`, pipes or redirects). **Reads outside the folder** are asked (Ask) or denied (Read-only).
- **Three Feathers About (spec 008 FR-018).** The app names **Three Feathers** as owner and credits vikramgorla, fjcabello and rubenlupi (GitHub handles) in the OS About panel and Settings > About, `LICENSE` and the installer metadata.
- **Chat and office (specs 005 to 007, 015 to 017).** Full-screen chat with a slim agent strip, previous sessions per folder (resume, plus read-only VS Code chat history), new session per folder, model and reasoning-effort pickers, a Thinking timeline, nested sub-agent blocks, safe Markdown in chat, collapsible room doors, a layout that fits 15 agents at 1440x900 and 1280x800.
- **Safer packaging.** `DURBAR_*` developer hooks are ignored in packaged builds unless `DURBAR_DEV=1`. The Copilot SDK is pinned exactly (1.0.22).

### Honest limits

- **Unsigned, not notarized** (signing is spec 014, a draft that needs the maintainer's approval to buy certificates).
- **Untested on real Macs and Windows PCs.** CI builds the macOS and Windows packages and runs unit tests on all three OSes, but no one has launched them on real hardware. The macOS/Windows About panel and installer metadata were not looked at. Only Linux was run by hand.
- Needs a GitHub Copilot login (`copilot login`); usage bills against your own plan. Independent project, not affiliated with GitHub or Microsoft.
- Known gaps are listed per spec (`[KNOWN GAP]`) and under "Known limits" in the README.
