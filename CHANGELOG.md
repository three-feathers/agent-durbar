## v0.1.1 ([release](https://github.com/three-feathers/agent-durbar/releases/tag/v0.1.1), 2026-10-28)

The first update after the first stable release, unsigned and not notarized like every build so far. Highlights: **List columns that follow their content and calmer room headers**, a readable folder name in every room header, a status pill that says what it hides, **Characters** as a Settings choice separate from themes (with the experimental Cheeky characters), a schedule's run history, **+ Folder** can create a new repository or an empty folder and clone a repository, one floor at a time when several floors are on, *Restart without the sandbox* for Copilot, a Running MCP server whose calls fail now says so, and release hardening (build provenance attestations, pinned Electron). Each entry names the spec and how it was checked; what was not run on a real Mac or Windows PC is written in the entry.

- **List columns follow their content; calmer room headers** (spec 001 FR-182..FR-184, issues #812, #813): in List, Agent app, Active, Usage and Status fit their text (with a cap), Agent and Folder keep more room so names show whole, Current task takes what is left and is the one that is cut, and Role no longer repeats the agent app ("no prompts · gpt-5.2" instead of "Copilot (no prompts) · gpt-5.2"); every cut cell shows its full text on hover and the row's screen-reader name keeps all of it, and a narrow window drops Role, then Folder, instead of scrolling sideways. In the office the rooms' bottom wall has no doorway notch any more, and the pencil in a room header is only an icon (a tile shows on hover or keyboard focus). Checked on the simulator at 1440x900, 1280x800, 1024x700 and 640x480 (`npm run check:listcols`).
- **The folder name in a room header is always readable** (specs 001 FR-179 and 059 FR-169, issue #788): the name keeps at least 8 characters (it was squeezed to two letters next to a floor tag, a schedule chip and MCP); when the header is tight the pencil, the schedule chip, MCP, the floor tag and the cost give way, one at a time, into the folder's ⋯ menu (which gains MCP extras and Cost); the folder pencil sits after the name, never over it; the name's tooltip shows the name and the path. ## v0.1.0 ([release](https://github.com/three-feathers/agent-durbar/releases/tag/v0.1.0), 2026-10-26)

The first stable release, unsigned and not notarized like every build so far. Feature freeze since the owners' decision of 2026-10-26 (spec 021 FR-059, spec 091): every known user-impacting bug is fixed or written as a known limit (spec 090). Highlights: **New reply marker and desk glow**, **Notes** (save a message, a drawer, header count), a clearer approval card for "for this session", honest spending-limit and Safety-model wording, a stable-release path in the tooling, and fewer flaky tests.

- **Helper-card repaint check no longer flakes under load** (spec 001, FR-169, #763): `test:helpercard` compares the best of 3 CPU times against a same-run baseline as a ratio (limit 20, timer-tick floor) instead of a fixed millisecond limit. Test only; a repaint that cuts the 1 MB result again still fails it (ratio about 4800).
- **A finished agent's reply is marked "New" until you have seen it** (specs 001 and 005, issue #691): when an agent finishes while its chat is not shown, its desk, list row and chat-strip item get a **New** badge (dot and word, a green glow on the desk, "new reply not read yet" in its accessible name, one announcement, a single pulse only when motion is allowed). It is a marker, not a state: the counts, sort, filters and permissions do not change, and an unread agent stays on its desk instead of resting on the couch. It clears when its chat is shown or with **Mark as read** in the card menu (also Shift+F10 / the Menu key on a focused desk or list row, new); closing the chat or going back to the office does not. Not kept across a restart. Simulator-checked (`npm run check:unread`, 67 unit checks, 1440x900 and 1280x800); not run on real sessions.
- **Desks now glow, and the person asks for attention** (spec 001 FR-178, owner request): a desk with a New reply glows green, and a desk that needs you (permission, question, limit) glows amber-orange and wins over New. No border; the card never moves. The person at the desk zooms in and out (three bigger pulses when it starts, then a slower one) while it needs you or has a New reply; with reduced motion only the static glow shows. The New badge and the status words stay, so colour is never the only cue.
- **A Copilot custom agent's subtask no longer shows a raw host error** (spec 002 FR-075, #703): the runtime's "Standalone server does not support session effect 'custom_agent_prompt'" now reads *Custom agents aren’t supported in Durbar yet. Run this agent in Copilot directly.* The session carries on. Custom agents still do not run inside Durbar. Unit-tested with the exact error text; not reproduced on a real session.
- The Settings list *What Durbar does not do* and the README now say spending limits are soft by one call (the call already running can go a little over), instead of "checked between replies". The README *Safety model* also says that an MCP server's read-only mark is trusted, that masking is best effort, which prompts Durbar stores, and that on Linux without a keyring the agent apps keep their sign-ins in plain files.
- **The approval card says how far "for this session" reaches** (spec 003 FR-013, FR-108): a write grant covers every file in the folder, and *Allow for this session: any arguments* covers every simple command of that name (`git` also `git push`); a plain line above the buttons says so. Tested with a unit test and a simulator check; the grant itself is unchanged.
- **Release tooling handles a stable tag** (spec 008 FR-129): a tag such as `v1.2.3` makes a draft that is not a pre-release and, published with `gh release edit v1.2.3 --draft=false --latest` (printed in the job summary), is the latest release; alpha, beta, rc and test tags stay draft pre-releases, never latest. The decision is one tested function (`releaseKind`) that `release.yml` reads. A stable release's notes say "unsigned build" instead of "alpha", and `changelog:build` accepts a stable heading. Checked by `npm run test:changelog` with planted mutants; the workflow first ran on v0.1.0's own release.
- **Stopping a Codex or Claude session ends its helper processes on Windows** (spec 012 FR-079): the close and kill steps use `taskkill /t /f` instead of ending one process. POSIX is unchanged. Checked with a fake child only; not verified on Windows.
- **`test-redact` no longer flakes under load** (spec 012 FR-080 delta, issue #684): the adversarial 1 MB cases compare their CPU time with a 1/16-size input of the same shape, best of 3 (growth up to about n log n passes), instead of a fixed 1000 ms limit, so a busy machine cannot fail a linear `redact()`; a quadratic rule still fails (checked with mutants). Test only.
- **The weekly test audit script no longer needs `flock` or GNU `stat`** (spec 021 FR-058): on macOS it uses a `mkdir` lock and BSD `stat`, which fixes `npm test` on the macOS release build. Linux behaviour is unchanged.
- **Weekly test audit** (spec 021 FR-058, harness only): every Friday a system timer on the owner's VPS has Claude Code audit the tests on a fresh copy of `main` (read-only, mutation-checked) as its own unix user with no token and no view of the owner's home, then a separate filing unit validates the answer (strict JSON, no links) and files at most 5 new, de-duplicated issues. Unit templates and install steps (sudo, by the owner) in `docs/agent-setup/`. Checked with `test:weeklyaudit` and fakes only (no real session); user-unit sandboxing was probed and does not apply on that host, hence the separate user.
- **Floor switch-off timing check no longer flakes under load** (spec 033 SC-003, issue #454): `shots-033` compares the switch's own time with a same-run yardstick (ratio limit 16, sanity cap 2000 ms) instead of a fixed 500 ms, so a busy machine cannot fail it; a per-agent delay or a repeated layout search still fails (checked with mutants). Test only.
- **Smaller screenshots** (spec 050 FR-012, issue #759): the pictures in the README and on the website are now 256-colour palette PNGs, 63% smaller (the 76 linked pictures went from 15.6 MB to 5.7 MB, the site from about 15.0 to 5.6 MB). `npm run shots:docs` compresses every picture it writes, and `npm run shots:compress` does it by hand; a quality guard keeps the original when a picture would look worse. Plain Node, no new dependency. Checked with `npm run test:compressshots`, `test:site` and one simulator retake.
- The website's wording follows the latest release: a stable release says "Download" and "Install Agent Durbar" instead of "alpha" (a pre-release keeps the alpha wording).
- **Rename pencil on wide cards** (spec 059, issue #781): when the mode icon wraps below the session name, the pencil sits after the name instead of over its first letters. `check-office-overlap` also fails a pencil over the first half of a name.
- **Notes: header count, saved-message marker and drawer search** (spec 083 T030..T032, issue 699): the chat header shows **Notes N** when the folder has notes (tooltip: how many are from this session) and opens the drawer; a message you saved shows a small note icon (*Saved to notes: <title>*) that opens the drawer on its note and goes away when the note is deleted; the drawer has a search field (title first, then text, case-insensitive; Esc clears it). Everything shown from a note is masked first. Checked on the simulator (`npm run check:notes-count`, `check:office` with the count shown and the drawer open, 300 notes open and search in under 100 ms); no real session and no screen reader.
- **Notes: no more lost note when several Durbar processes take over a stale lock** (spec 083 FR-008, issue #723): only one process at a time may break a stale lock, a lock is released only if it is still the releasing process's, and a writer that lost its lock stops instead of writing; leftovers of a crash are swept. Tested with an injected file system and with four real processes on Linux. Not run on Windows or macOS: delete-pending errors on creating the lock, antivirus read errors, NTFS inode and time values, hard links on FAT/exFAT, and rename-aside behaviour.
- **Notes: save a message, the Notes drawer and notes in the `/` list** (spec 083 T020..T024, issue 699): every finished message has a **⋯** with **Save to notes**; a drawer over the chat log (More > Notes…, Ctrl+Shift+M / ⇧⌘M, Ctrl+K *Notes*) lists this session's and the folder's notes with **Insert** (into the message box, never sent), **Edit…**, **Rename…**, **Delete…** and **+ Note**; the `/` list offers notes after the commands, also in a chat whose agent app lists no commands. Notes are stored on this computer (0600) and masked first, and the window masks again. Checked on the simulator (`npm run check:notes`, `check:office` with the drawer open) and with unit tests; no real session and no screen reader. The notes count, the saved-message marker, search, selection save, the per-folder screen and the project file are the next slice.

## v0.1.0-alpha.7 ([pre-release](https://github.com/three-feathers/agent-durbar/releases/tag/v0.1.0-alpha.7), 2026-10-19)

Unsigned and not notarized; only Linux was run by hand. **OpenAI Codex** is now offered next to Copilot and Claude Code when it is installed and signed in.   - a mode switch from the next message, models and efforts;
  - previous sessions and resume; a folder continues its last thread after a restart.
  
  Checked end to end in the real app with ChatGPT Plus. On Ubuntu, Read-only and Ask first need the bubblewrap note in the README.

An ended Codex session continues its own thread, also after a restart. Checked on a real Codex.

All of this was checked on a real Codex.

- **For anyone with agents, across harnesses (spec 001 FR-027).**
  - The welcome card, the README, the app description and the repository description now say what Durbar is: a calm command center for AI agents on GitHub Copilot, Claude Code and (in progress) Codex, for code, documents, research or notes, not only for developers.
