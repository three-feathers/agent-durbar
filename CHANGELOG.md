# Changelog

Agent Durbar is an alpha. Builds are unsigned and have only been run by hand on Linux (see "Honest limits"). Each entry names the spec that describes the behavior and how it was checked.

## Unreleased (on `main`, after the alpha.3 tag)

- **Switch model and context inside a session, simulator only (spec 030 Phase 1, tasks T016..T024).** Chat-header model chip is a menu (price per million tokens or "price not reported", window, effort, Long context only when offered, queued switch with Cancel); pricier, unpriced, long-tier or over-cap-headroom switches ask first, cheaper ones apply with an **Undo** toast; the credit cap never changes. The context chip shows the tier, "Window: waiting for next message" after a switch, and a **Compact** action (idle agents only, optional focus). Compaction (manual, automatic, before a smaller window, failed) leaves one chat line; a dismissible start-fresh note offers New session near the limit. A model change by the runtime (rate limit, refused request) is shown as a note and a toast and never saved as the folder's choice. **Office card menu:** right-click, then *Model and context...*. **Real Copilot agents are unchanged in what they can do:** the model chip opens a menu that says it cannot switch in place and offers New session; they do now show compaction lines and the start-fresh note when the runtime reports them. Checked by `npm test` (new `test:modelswitch`, `test:simmodel`; additions to events, folders, dialog tests), `npm run check:model` (real key events in the simulator, 1440x900 and 1280x800, screenshots `docs/screenshots/030-*`) and `check:office`; **no real session, 0 AIU**. Sim prices, windows and queue behaviour are made up; the real runtime's are unverified (`[KNOWN GAP]`).
- **Switching model and context, groundwork (spec 030 Phase 1, tasks T010..T015, simulator only).** No visible change with a real Copilot account: its agents still show the model as read-only and have no switch or compact action. Added the pure price and confirmation logic, the normalized `model` and `compaction` events and the mapper for the matching SDK events, the folder store's `contextTier`, main-process IPC with validation (`agents:setModel`, `agents:cancelQueuedModel`, `agents:compact`; real agents answer "start a new session"), and simulator support (priced fake models, a long-context tier, queued switches, runtime fallback, manual and automatic compaction). Checked by `npm test` (`test:modelswitch`, `test:simmodel`, additions to `test:events` and `test:folders`); no real session was started. The sim's prices and queue behaviour are made up; the real runtime's are unverified (`[KNOWN GAP]`, spec 030 research).
- **Docs only, no behaviour change:** spec 030 (change the model and the context window inside a session) is researched, specified, planned and split into tasks ([specs/030-switch-model-context](specs/030-switch-model-context/spec.md)). Copilot SDK 1.0.22 declares a live model switch (applies from the next message, queued while a turn runs), a manual compaction and a long-context tier, but no free window size and no clear from a host app; this was read from the SDK types and docs only. Nothing was run on a real account and no credits were spent. Not built: a session's model still cannot be changed in the app.
- **Import from VS Code, per folder (spec 020 FR-020..FR-031, issue #7).** A folder's MCP extras screen has **Import from VS Code...**: it reads that folder's `.vscode/mcp.json` (comments and trailing commas are fine), shows a preview with a checkbox per server (nothing ticked, env/header keys with masked values, ignored fields and unusable entries explained) and adds the ticked ones as extras of **that folder only**, switched **off** and not trusted, so the first switch-on shows the trust dialog. VS Code `inputs` are never asked for, stored or resolved: values with `${...}` references are not copied, and entries that need one in their command, arguments, URL or working directory (other than `${workspaceFolder}`) cannot be imported. The VS Code file and `~/.copilot/mcp-config.json` are never written, and nothing is added to the global list. Unit tests in `test:mcp`, simulator screenshots `docs/screenshots/i7-import-preview-*.png`; no credits spent, not checked on a real VS Code file, macOS or Windows.
- **Docs only, no behaviour change:** spec 012 (Claude Code and Codex adapters) is clarified, researched, planned and split into tasks ([specs/012-claude-codex-adapters](specs/012-claude-codex-adapters/spec.md)). There is no Claude or Codex adapter yet and nothing was tried on a real account.

- **Keyboard focus in the Allow all confirmation (spec 003 FR-033, issue #25).** Focus used to jump back to the mode chip behind the dialog, so Escape did nothing and Tab left the dialog. Now focus stays inside it, Tab is trapped, Escape cancels (mode unchanged) and focus returns to the chip. *Allow all* still needs an explicit confirm. Tests: `npm run test:dialog` (in `npm test`) and `npm run check:dialog-focus` (simulator, real key events).
- **Docs only, no behaviour change:** the two README hero pictures (15-agent office, full-screen chat) and the Settings/About, credit-cap and MCP pictures (`m9-office-caps`, `m9-settings-cap`, `m10-*`, `about-settings`) were regenerated on the simulator, so they show the office total, per-folder totals, the Tools/Settings buttons, *Import from VS Code...* and the alpha.3 version. New drivers `scripts/shots-hero.js` and `scripts/shots-about.js`; `shots-m9.js` and `shots-m10.js` now hide the startup toast. `AGENTS.md` no longer lists spec 012 as a backlog draft (spec 025 FR-006).

## v0.1.0-alpha.3 ([published pre-release](https://github.com/three-feathers/agent-durbar/releases/tag/v0.1.0-alpha.3), 2026-10-17)

Published by the maintainer as a **pre-release** (it was built as a draft first). It is the first published release. Small update on top of v0.1.0-alpha.2 (never published; its draft was removed in favour of this one, the [git tag](https://github.com/three-feathers/agent-durbar/tree/v0.1.0-alpha.2) remains): the permission mode rename, usage totals, Windows grant-scope tests and a docs catch-up. Spec: [026](specs/026-release-alpha3/spec.md). Built and tested on the simulator and unit tests; **no AI credits were spent for the release itself.**

### Read this first

- **Still unsigned and not notarized.** macOS: right-click (Control-click) the app, choose **Open**, or `xattr -dr com.apple.quarantine "/Applications/Agent Durbar.app"`. Windows: SmartScreen "More info", then "Run anyway". Linux: `chmod +x` the AppImage.
- **Untested on real hardware.** Only Linux has been run by hand. The macOS and Windows packages are built and unit-tested by CI, but nobody has launched them on a real Mac or Windows PC.
- Same app id as alpha.2 (`io.github.three-feathers.agentdurbar`), so it should be the same app as alpha.2, but an in-place upgrade from alpha.2 was not checked. No auto-update. Download newer releases by hand.

### What's new

- **Permission mode renamed *Allow all*** (was *Allow edits*), in the top bar, new-session dialog, mode chip and menu, confirmation, toasts and chat hint. Behavior is unchanged: it approves everything. Names are now Read-only / Ask first / Allow all. Spec 003 FR-028..FR-030, PR #15.
- **Usage totals (spec 011 FR-018..FR-023, PR #17).** An office total (header chip) and a per-folder total (room header and closed door plate) in AIU, summed from the runtime's usage events since the app opened. Not saved across restarts; ended sessions stay counted; shows "credits not reported" instead of 0 when the runtime sends no figure. `npm run test:usagetotals`.
- **Windows paths in session-grant scopes** are unit-tested (spec 003 FR-031/FR-032, PR #16). Known gap: Windows grant keys are not yet compared case-insensitively (task T028).
- **Docs and process:** README, CHANGELOG and spec statuses brought in line with `main`; AGENTS.md has a "Keep docs in sync" rule; the PR template has a "Docs updated" box; a non-blocking check warns when `src/` changes without a docs change (spec 025).
- **Screenshots of the mode menu, confirmation and right-click menu** (`docs/screenshots/m7-mode-switch.png`, `m7-mode-confirm.png`, `m7-mode-context.png`) were regenerated on the simulator and now say *Allow all*; the driver is `scripts/shots-mode.js` (spec 025 FR-005, T006).

## v0.1.0-alpha.2 (never published, 2026-10-16)

> The alpha.2 draft was deleted and replaced by alpha.3, which includes everything below. The git tag `v0.1.0-alpha.2` remains.

Everything since [v0.1.0-alpha.1](https://github.com/three-feathers/agent-durbar/releases/tag/v0.1.0-alpha.1) (milestones 6 to 10 plus ownership). Spec: [023](specs/023-release-alpha2/spec.md). Built and tested on the simulator and unit tests; the real Copilot runtime was used only for small research captures (about 0.17 AIU) and free checks. **No AI credits were spent for the release itself.**

### Read this first

- **New app id: `io.github.three-feathers.agentdurbar`** (was `io.github.vikramgorla.agentdurbar`; spec 008 FR-019). The old test install is a **separate app**: it does not share settings, saved folders or tool counts with this one, and installing alpha.2 does not replace it. Remove the old one yourself if you do not want both.
- **Still unsigned and not notarized.** macOS: right-click (Control-click) the app, choose **Open**, or `xattr -dr com.apple.quarantine "/Applications/Agent Durbar.app"`. Windows: SmartScreen "More info", then "Run anyway". Linux: `chmod +x` the AppImage.
- No auto-update. Download newer releases by hand.

### What's new

- **MCP servers (specs 019, 020).** The **Copilot CLI's own list** (`~/.copilot/mcp-config.json` plus the built-in GitHub server) is read live and is the primary, global source in Settings and in the Tools view, with call counts and the exact command or URL (no env or header values). Nothing to import. Extra servers that only this app passes to a session are stored **per folder or workspace** (room-header MCP button) with a trust prompt that shows the exact command; secrets stay encrypted with the OS store. Servers from the CLI list get no trust prompt (decided by Vikram, 2026-10-16). The old app-level list and its Import buttons are gone.
- **Tool usage (specs 019, 020).** The Tools view has **This session** and **All time**. All time is kept on disk (`durbar-tool-usage.json` in the app's userData folder) and survives restarts: per tool, per MCP server, per agent. Only tool names, server names, agent labels and counts are stored; never arguments, output, prompts or paths. A second tab shows models and the context window used per agent. **Reset all-time counts** clears it.
- **Credit caps (spec 011).** Optional AI-credit cap per session (runtime minimum 30), set in the new-session dialog or from the chat header chip, with a global default in Settings. Cards and the chat header show used/cap; it is a **soft** cap (one response can overshoot). When reached: **Limit reached**, then Add credits / Remove cap / Stop here. `[UNVERIFIED]` against a real exhausted cap (it costs real money); covered by fixtures and the simulator.
- **Permissions (specs 003, 018).** Change an agent's mode (Read-only, Ask first, Allow all) any time. The saved mode of each folder is **restored exactly** after a restart, *Allow all* included, with a visible *restored* note until you change it; switching to Allow all still asks for confirmation. (The alpha.2 build itself still labels the last mode *Allow edits*; it was renamed *Allow all* right after, see alpha.3.) *Approve for this session* grants never survive a restart. Shell grants cover the **exact command** unless you explicitly choose "any arguments" (never for shells, interpreters, `sudo`, pipes or redirects). **Reads outside the folder** are asked (Ask) or denied (Read-only).
- **Three Feathers About (spec 008 FR-018).** The app names **Three Feathers** as owner and credits vikramgorla, fjcabello and rubenlupi (GitHub handles) in the OS About panel and Settings > About, `LICENSE` and the installer metadata.
- **Chat and office (specs 005 to 007, 015 to 017).** Full-screen chat with a slim agent strip, previous sessions per folder (resume, plus read-only VS Code chat history), new session per folder, model and reasoning-effort pickers, a Thinking timeline, nested sub-agent blocks, safe Markdown in chat, collapsible room doors, a layout that fits 15 agents at 1440x900 and 1280x800.
- **Safer packaging.** `DURBAR_*` developer hooks are ignored in packaged builds unless `DURBAR_DEV=1`. The Copilot SDK is pinned exactly (1.0.22).

### Honest limits

- **Unsigned, not notarized** (signing is spec 014, a draft that needs the maintainer's approval to buy certificates).
- **Untested on real Macs and Windows PCs.** CI builds the macOS and Windows packages and runs unit tests on all three OSes, but no one has launched them on real hardware. The macOS/Windows About panel and installer metadata were not looked at. Only Linux was run by hand.
- Needs a GitHub Copilot login (`copilot login`); usage bills against your own plan. Independent project, not affiliated with GitHub or Microsoft.
- Known gaps are listed per spec (`[KNOWN GAP]`) and under "Known limits" in the README.
